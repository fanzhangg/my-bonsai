# 盆栽生长算法研究与 MVP

本文记录早期芽竞争实验；当前首页实现请看 [盆景算法当前实现](盆景算法当前实现.md)。

研究日期：2026-09-16。目标：研究初始盆栽、几天的生长、剪后回芽和随机差异。当前界面仅保留算法操作，研究说明留在本文；不包含双人玩法、冷却或评审表单。本原型是 v0.5 设计的算法实验分支，不代表正式产品已改用此模型。

## 1. 研究结论

建议先评审 **二维简化芽竞争模型**，保留规则分叉作为可对照基线。它能让“剪一刀”改变后续生长机会；若视觉结果满意，再决定是否升级空间搜索和光照模型。没有必要为这个 MVP 先实现三维植物生理模拟。

| 路线 | 文献支持的能力 | 对这个产品的判断 | 本次使用方式 |
|---|---|---|---|
| 参数化／随机 L-system | 重写规则和 turtle 几何表达递归分枝；也可扩展表达环境响应 | 便于确定性回放，但简单二叉模板易显规则 | 规则分叉基线采用类似的递归思想，不实现完整语法解释器 |
| Space colonization | 吸引点分配给附近枝节点，枝条沿合成方向延伸，并移除已占据的吸引点 | 适合树冠轮廓和空间填充；剪后吸引点是否恢复，需要另行设计 | 只借鉴争取空余空间的想法，原型使用候选方向评分，不声称实现该算法 |
| Self-organizing tree model | 芽与枝争夺光或空间，并由内部信号调节；论文包含剪枝和弯曲交互 | 与“剪后重新分配生长机会”的目标最吻合 | 简化为光照评分、空间评分、顶端优势、每步有限生长预算和剪后芽唤醒 |

这些取舍是本项目的工程判断，不是论文对盆栽游戏的推荐。主设计文档附录“L-system 不会对剪枝有反应”过于绝对：作者的 1995 年章节明确给出休眠芽因剪枝而激活的 L-system 示例。[The Algorithmic Beauty of Plants，第 1 章](https://algorithmicbotany.org/papers/abop/abop-ch1.pdf)、[Runions 等，2007](https://algorithmicbotany.org/papers/colonization.egwnp2007.html)、[Palubicki 等，2009](https://algorithmicbotany.org/papers/selforg.sig2009.html)、[Prusinkiewicz 等，1995，§8.3.1](https://algorithmicbotany.org/papers/handbook.95.pdf)。

论文的时间尺度不是本游戏的“三天”。论文模型也不是针对某个盆栽树种的养护预测。这里的时长、永不死亡、深度上限和回芽窗口均由产品需要设定。

## 2. 实际实现了什么

入口：`npm start`，访问 `http://127.0.0.1:4173`。模型代码在 `prototype/model.mjs`。

### 初始树与时间

- 根枝先在内部生长 18 个虚拟小时，用户从第 0 小时看到已有侧枝的幼树，不展示种子阶段。
- 固定步长为 0.5 虚拟小时。先处理同刻自然生长，再按序应用该刻剪枝，因为用户确认的是已经看到的树形；初始树、每次剪枝和任意历史帧均可复现。
- 每枝最多有两个子枝位置，最大深度 7，最多 255 根存活枝。默认模型在数个虚拟日内形成稳定树冠；休眠芽可在剪枝后重新获得机会。
- 不承诺遵守 v0.5 规则模型的 60.1–81.9 小时精确范围：芽竞争会延迟或抑制分枝。实际完成时间需要在参数评审中决定。

### 生长决策

每个子枝位置有可萌发时刻、累计生长信用和激活窗口。规则基线在到期时生成枝条；芽竞争模型每个半小时重新计算候选芽：

```text
受光 Q = exp(-附近上方枝梢造成的遮挡近似)
空间 S = clamp(到其他枝梢的最近距离 / 25, 0.08, 1)
顶端系数 A = 有主梢的侧芽 ? 1 - 0.6 × 顶端优势 : 1
竞争权重 W = (0.3 + 0.7Q) × (0.3 + 0.7S) × A
信用增量 = 0.5 × 0.8 × W
```

信用达到 1 后获得萌发资格，每步最多生成 3 根新枝，按权重与稳定 key 排序。同一模拟步的评分基于更新前的树，避免遍历顺序改变本步评分。未在六小时窗口内获得机会的普通芽休眠。这个全树预算是简化的资源竞争，不是论文的层级激素／资源分配公式。

每个芽比较 5 个候选方向，综合受光、与其他枝梢的距离及偏离自然方向的代价来选择方向。计算在二维平面进行；没有三维遮挡、叶面积积分或真实光线追踪。

### 剪后反应

选枝只高亮，确认才记录剪枝。剪去整段子树，主干不能剪。约四小时后在原父枝相应位置生成新的生长谱系，候选方向偏离被剪的枝，并重新评估附近空间。半小时步长意味着实际出芽显示会向下一个模拟步取整，最坏增加不足半小时。

芽竞争模式还重新开放断口附近 95 单位范围内的未萌发芽窗口：附近的受光和空间改变后，这些芽可能萌发。已长成枝条的几何不被重写。规则基线保留定时回芽，但没有邻近芽竞争唤醒，便于对照剪枝的二次影响。

这里的回芽位置与唤醒半径是人为规则，不是已验证的树种生理。若 review 认为像“自动补回原树”，下一步优先改这部分。

### 随机与粗度

随机值以 `hash(seed, growthKey, property)` 产生，分别控制枝长、弯曲、节奏与方向。随机样本与客户端事件 UUID 无关，换一次请求 ID 不能重抽。不同树有不同形态，同一树重复回放一致。

枝粗使用下游生长量的平方根作为视觉近似，并保留历史最大粗度，因此剪掉叶子不会让旧木头瞬间变细。这只是受分枝截面积思想启发的绘制方式，不是严格管道模型，也没有碳分配和木质部模拟。

## 3. 可以评审的操作

- 两种算法切换；可输入 seed，调整顶端优势、光照方向和微扰。
- 时间轴、快进 4 小时／1 天、主动触发的全程回放与跳到时间线终点。
- 两步剪枝确认；任何模拟时刻均可剪，同一时刻可以连续剪，播放时选枝自动暂停。
- 未修剪的同种子树灰色叠加；仅枝干视图；芽点／休眠状态。
- 缩放、拖动、密集枝条候选选择；手机响应式布局。
- 本机保存实验，导出包含参数、事件和模拟时间的 JSON。

改变 seed、模型或参数会从初始幼树开始新实验，不能将旧枝 ID 的历史套到新树上。导出后可重新导入原实验。在过去剪枝会保留该时刻及之前的动作，截断之后的动作并从这里重新模拟；原时间线单独保留一份本机备份，可导出恢复。连续历史编辑时备份更新为最近一次编辑前的场景。

## 4. 限制和待评审项

1. 二维近似会把深度上错开的枝视为相互遮挡；平面交叉也可能显得拥挤。
2. 默认左右主枝骨架仍有人工造型痕迹。初始随机性是否足够、树是否像盆栽，需要视觉评审。
3. 不发生枯死、自然落枝或季节变化；最终静止是当前产品规则。
4. 半小时离散状态下，播放表现为一连串小步变化，没有实现连续插值和完整掉落动画。
5. 客户端沙盒没有 Neon、双人同步或剪枝额度；旧事件中的操作者字段仅用于场景兼容，不影响操作。
6. 默认开放上帝模式，因为页面仅由本机静态服务器提供；公开部署前仍需按主设计加入调试隔离与鉴权。
7. 对照是“同种子、同参数、不剪枝”的反事实，不是另一种算法。切换算法会新开实验，不能把两个模型的枝 ID 当成可对应的相同枝条。

## 5. Review 建议

优先回答：

- 第 0、1、2、3 天分别像什么？哪一阶段最像盆栽？
- 主干粗细、分枝角度、叶团密度、左右平衡是否自然？
- 剪枝之后四小时与一天的变化，是否能与那一刀建立联系？
- 看灰色未修剪轮廓时，剪枝是否明显改变形态，而不是只延迟恢复？
- 芽竞争相对规则分叉的改善是否值得增加模型复杂度？
- 手机选枝时，是否看得清自己将剪掉什么？

场景导出文件带上 seed、参数、动作日志和模拟时刻；描述“哪根枝、哪个时间”的问题可直接复现。

## 6. 本次验证

- 自动化测试覆盖逐帧与直接跳时的一致性、20 个 seed 的初始可剪性和稳定性、剪除子树、旧木粗度、回芽延迟、取消失去父枝的芽、未来事件不改过去、重复修剪、主干保护及 JSON 导入校验；另增加同一时刻连续剪枝和历史时间线编辑的验证。
- 默认 `MOSS-0826`、默认参数、无剪枝：第 4 天芽竞争模型有 190 根枝、78 个末端、35 个休眠芽；最后一根存活枝约在领取后 90.9 小时长足。规则基线为 255 根枝、128 个末端。这是当前实现的运行结果，不是文献给出的盆栽数据。
- 初版浏览器验证覆盖选枝后独立确认、剪枝记录、回芽出现与未修剪轮廓叠加。当前版本不再自动播放开屏回放。
- 320 与 390 像素响应式视口没有页面横向溢出，手机尺寸下能打开选枝确认面板。尚未进行真实 iOS／Android 设备的触摸、性能和辅助技术验收。
