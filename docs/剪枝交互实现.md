# 剪枝交互

认养后按下右下角剪刀，树上显示可剪旁支的圆形提示点。按住拖动时靠近提示点吸附，松手剪除整根旁支及所属细枝、叶片；也可点击拿起剪刀，移动到提示点后再次点击剪下。提示点为 8px 半透明灰绿色小圆点，选中后增至 10px 并显示一圈淡细线，对应枝叶仅轻微提亮。移除所有可见文字提示、选中标签和剪刀投影；操作状态仅供读屏使用。键盘选中使用同样的提示点与反馈。

提示点位于旁支靠近根部的位置，并避开主干保护区域；尚未生长、已剪除或没有露出主干的可剪位置的枝条不显示点。吸附范围为屏幕 30px，选中后离开 44px 才解除，移动到更近的提示点可切换。只允许 `primary` 旁支；主干不吸附且服务端拒绝剪除。没有确认、撤销、返回按钮或剪枝倒计时。空白处松手或点击、Esc、拖动中断、滚动页面、窗口失焦均归位，不剪枝。归位与剪下时移除所有提示点。

剪刀使用灰色刀刃、绿色握柄和铜色轴心的纯色色块；拿起后每 1.7 秒缓慢开合。落剪从当前角度在 180ms 内合刃；保存成功后，枝叶旋转落下约 900ms，剪刀在 320ms 内归位。不添加伤疤。减少动态效果时停止循环并缩短落剪动画。

`pruning.mjs` 由 design system 和真实界面共用。拖剪期间暂停风动、访客和定时同步，避免目标位移或画布被替换。支持鼠标、触摸和键盘；键盘用空格拿起、方向键选择、空格剪除。

`POST /api/trees/:id/cuts` 接收 `{id, branchId}`，其中 `id` 是操作 UUID。服务端在存储事务中验证当前活枝、拒绝主干及已删除的枝条，记录服务端时间和顺序号。相同操作重试不会重复写入；网络异常自动以同一个 UUID 重试一次。失败时保留枝条，显示保存错误，可重试同步。沿用现有固定链接访问模式，无新增账户或权限系统。

`growth.mjs` 根据事件时间过滤完整枝系，连同尚未出生的子枝一起剪除，保留剩余枝条的几何和生长进度。`regrowth.mjs` 在活旁支少于原始旁支数量的一半（向上取整，至少两根）时自动补枝：每隔 4–8 小时，从空缺枝位中随机选一处萌芽，直到恢复到该数量。新枝的角度、长度和着生位置有小幅随机变化，保留树形特征；主枝约 12–18 小时伸展，随后逐级长出细枝和叶片。成熟树同样可以补枝，再次剪掉新枝后仍会继续补充。

随机结果由树的种子及补枝序号决定；时间线由剪枝记录重建，离线期间也会生长，刷新、服务端校验、开场回放和作弊模式保存一致。新枝使用独立编号，旧枝及未出生的旧子枝不会复活。Debug 中的剪枝仅修改本地样本；设计系统中的「生长 8 小时」与「重置样本」可用于预览剪后恢复。

测试覆盖七种树形的剪前历史、剪后持久化、未来子枝过滤、主干保护、重复请求、并发提交、存储重开、回放一致性和风动暂停恢复，以及稀疏和全剪后的补枝、渐进生长、反复修剪、随机结果稳定和新枝保存。
