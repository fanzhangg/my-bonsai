# v3 剪枝、生长与作弊模式集成

本次渐进补枝改动仅在本地，供审核，未提交或推送。独立原型 `adaptive-growth.html` 保留；正式 v3、设计语言页、设计系统剪枝页使用同一版算法。

## 交互与恢复

- v3 允许一级侧枝，以及其下一级侧枝被剪除。主干、承重分叉 `bough` 与更细末梢受保护；分级依据父子关系，不直接使用各树形含义不一致的 `branchOrder`。v2 保持原有一级旁支规则与图形快照。
- 共用原有鼠标、触摸、键盘剪刀操作和落枝动画。二级提示点用虚线边缘区分；服务端、剪刀命中和作弊校验共用 `canPrune`。正在萌发、尚未达到生长阈值的侧枝不可剪。
- 一级侧枝按主干/承重枝顺序建立候选区域，但生长机会和枝量预算在整树共享。理想值为原树形一级枝数；下限累加各区的理想枝数减一（各区至少一根）作为整树恢复目标，不要求每个被剪空的区域原位补齐。非文人式且原本至少四根一级枝的整树上限为理想值加一，其余沿用理想值；每个候选区域最多容纳原始该区枝量加一，整树总量仍不得超限。剪掉下方枝条后，可以在上部生长，而不强制恢复下部原轮廓。二级枝建议每根母枝一至两根，约三成枝系允许自然长至三根。文人式只允许少量二级冗余；第三层细枝沿用原枝系的数量上限（零至两根），避免靠不可剪的小枝无限填满树冠。统计包含已经出生、尚在伸展的枝条，避免重复补枝。
- 新盆栽配置保存 `growthPolicy: natural-5`，基础树形成熟后自动进入自然添枝阶段。新操作使用 `state-8`，旧树从首次新剪枝起启用本规则。剪枝不会即时生成可见枝条、不会赠送十二小时生长量；不足下限时提高后续萌发概率。下限是恢复目标，不阻止用户主动剪成更稀疏的树。
- 每两生物小时一次机会：低于下限时概率为 70%；下限至理想值之间为 `30% × 缺少的理想枝数 / max(1,理想值−下限) × 生长活力`；达到理想值后基础概率降到一级 3.5%、二级 4.5%，再乘生长活力。活力从基础树形成熟时的 1.6 倍按 `max(0.5, 1.6 / (1 + 成熟后小时 / 72))` 衰减，概率封顶 70%。达到数量上限停止排期。按本次排期的概率采样首次成功轮次；刷新不重抽。新生一级枝用八个生物小时、二级枝用六小时逐渐伸展，叶片随后展开；父枝成熟后才开始下一层生长，最深到第三层。浇水沿用统一生物时间。这里采用加速的视觉生长尺度，不声称模拟真实植物的小时级生长速度。
- 自然冗余枝仍沿用树形与连接约束，但允许略宽的局部角度变化，二级枝可从母枝更靠内的位置长出，逐渐填入留白并产生轻度重叠。所有冗余均在可剪的一、二级枝上；剪掉后不立即长回，后续仍按较低概率自然再长。
- 新枝从当前活树的可用空间、母枝方向、树形与稳定随机源选取着生点及曲线。只决定当次新枝，不复制被剪家族；未来子枝出生时再次读取当时状态。保留已有木质枝、树形配色及固定相机。
- 补枝首先遵守树形轮廓、活母枝连接和可见性约束，其次避免接触已有枝干，再按枝条空间、叶冠空隙和上方透光条件选址。以当前存活叶冠做二维椭圆遮挡近似，沿新枝取样并向上方五个方向估算透光；已出生的新枝提前保留部分叶冠空间，避免后续新枝挤入同一个空隙。一级枝每次在全树仍有容量的候选着生点中选择。选址把可用着生点的垂直范围分为六个连续高度区间，从最高区间逐层向下检查。每层先检查树形、连接、可见性约束，以及枝干净距至少 2、末端间距至少 12（设计坐标）、叶冠空隙值至少 0.62、透光值至少 0.6。选中第一个合格的高度区间后，再按空间、透光和剪口距离等条件选具体位置；因此顶部不合适会先检查中上部和中部，不会因为底部稍亮就跳过合格的中部。所有区间都无合格点时选择约束冲突最少的位置，不固定补回剪口，也不无限重试。悬崖、风吹等树形仍只在原有结构允许的候选点中筛选，避免为追高改变树形。二级枝仍连接原来的存活母枝，不会从下部母枝移接到树顶。不设置剪口禁生半径：剪口附近如果更空、更透光，可以优先长枝。此模型近似天空散射光，不随昼夜和天气重新选址。最近 72 个生物小时最多六处剪枝及局部任务的剪口偏好仍保留为次要条件。
- 补枝复用设计系统的树形长度档位、分级粗细与母枝切线连接规则。着生点和参考枝系绑定，方向只在该枝系的有限范围内变化；子枝保留参考枝系，避免连续补枝后逐代偏转。风吹式收紧角度范围，悬崖式保留局部下垂方向，年轻末端轻微上扬。新枝逐级缩短、变细，并优先留在原枝系的冠幅范围和已有木质枝之间的空隙内。空间避让和远离剪口的评分只在这些树形约束内选择；这是一组视觉生长近似规则，不是完整植物生理模拟。
- 只保留原来的剪下、落枝反馈；补枝没有独立动画、装饰芽或时间快进。随真实时间更新和调试时间推进，统一生长引擎显示同一根新枝的逐渐伸展。剪去冗余后留白持续存在；长期无人修剪才缓慢长出可修剪冗余，使修剪选择能影响后续树形。

## 作弊模式 UX

“生长进度”与“可剪数量”分开：基础树形到 100% 后仍可继续自然生长。面板展示一级/二级可剪数量、建议范围与自然上限，并提示当前比建议多出的侧枝数和修剪留白的用途。提供 +1 小时、+12 小时、+1 天；原“重播”改称“重播当前树形”，避免与推进生物时间混淆。

回拨只查看过去，不自动丢失未来剪枝/浇水。存在后续操作时暂停两项互动，显示数量和“从当前时刻继续（移除后续操作）”；用户执行后才删掉未来事件、重新推演，并可撤回。保存回拨时间仍可保留未来事件，它们在对应时间生效。

更换树形、种子、变化幅度或枝量会清空剪枝，提示明确写出影响，并提供撤回；冠型、叶形、配色保留剪枝。保存/重新载入后清空撤回状态。手机上剪刀、水壶和顶部按钮随树画布滚走，避免覆盖下面的作弊表单。

作弊保存的剪枝上限从 64 提高至 4096，认领和作弊保存的请求体上限提高至 1 MiB，其余操作保持 8 KiB。持久化的原始历史可在时间整体平移后保留；改动过的历史必须按当时活树重新验证。未出生、已剪掉、更深层或伪造枝条不能通过保存。

## 版本与历史

新 v3 剪枝事件记录 `model: state-5`。新首页预览、认领、设计审核样本均显式使用自然生长配置；旧树从首次新剪枝起切换，更换树形、种子或枝干参数的新调试样本也启用本规则。旧 `state-1`、审核阶段的 `state-2` / `state-3` / `state-4` / `state-5` / `state-6` / `state-7` 及 `natural-1` / `natural-2` / `natural-3` / `natural-4` 在切换前仍按原规则回放，保留已有枝条编号和形状。旧打开页面的认领请求不携带新策略时仍保留其原预览，不强行重写历史。新生枝编号为 `sprout:<序号>`，首次剪枝前自然长出的枝条也可剪除、保存、重新载入。存储格式仍是树配置与事件，Gallery、分享图及回放沿用同一个 `snapshot` 分发入口，无数据库 schema 变更。

已有包含旧 `regrow:` 剪枝记录的 v3 树在第一次新交互前继续回放旧补枝逻辑。首次新剪枝时，以当时的存活枝系建立恢复基线，保留旧编号和几何，之后使用新恢复规则。已剪旧枝不会复活；切换前的历史继续可回看。尚在伸展的旧恢复枝在切换时保留当时形态，后续通过新侧枝继续扩展。

## 审核与验证

遮挡枝条仍保留剪枝入口：一级、二级侧枝的提示点优先沿枝条分散摆放；完全被主干遮住或与其他点重叠时，移到附近空位并用细线连接真实枝条。选中后在最上层显示枝条轮廓，点击、拖动与键盘使用同一组目标；主干保护规则保持有效。回归样本包含用户反馈的风吹松种子 `ebf20375-015b-49e8-b3ee-641f811e558b`、变化幅度 0.85、217 小时，以及七种树形在桌面和手机缩放下的逐枝命中检查。

入口：`/bonsai-design.html`（完整设计语言加剪刀）、`/design-system.html` 的剪枝页、`/?cheat=1` 或已认领树的 `?cheat=1`。

建议依次检查：新样本零次修剪，快进数日观察轻度冗余 → 剪去冗余枝，确认没有补枝动画且留白保留 → 同一母枝二级枝剪至零，确认当下仍为空，+1 小时、+12 小时观察渐进恢复 → 长时间快进确认枝量上限 → 保存、重载、时间回拨检查一致性。比较文人式与其他树形的疏密、剪口附近留白及新枝方向。

新增测试覆盖七种树形两级剪枝、局部恢复、反复全剪、父子引用、浇水与重基时间一致性、非法剪枝、旧编号迁移、API 幂等、存储重开及超过旧请求大小的长历史保存。另运行仓库完整测试，并在浏览器检查键盘二级剪枝、恢复提示、作弊保存、回拨分支及手机布局。存储集成测试使用本地 JSON，不代表真实 Neon 生产验证。

本版空间评分仍是二维的简化规则，包含末端间距、画框与树形方向约束，未模拟完整生理过程或所有枝条曲线碰撞。请重点审核新枝外形、恢复速度和两级剪枝提示点的易用性。
