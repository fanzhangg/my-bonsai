# 我的盆栽 · MVP 设计文档

*v0.5 · 2026-09-16*

部署与存储使用 Render Web Service + Neon PostgreSQL：Render 提供网页和 API，Neon 保存树、参与者及剪枝事件。生长按时间计算，不需要后台定时推进。本版以手机交互为优先，加入出生即有枝条的随机幼树、全程开屏回放、剪前确认、轻微自然随机性和开发者上帝模式。

## 1. 概述

我的盆栽是一个双人异步、以手机为主要入口的网页体验：两个人共同养一棵盆栽，领到的是已经有可剪枝条的随机幼树。盆栽在几天内长成，两个人在各自方便的时候修剪。剪下时能立即看到枝条消失，新的生长方向则要几小时到几天后才显现。树形来自初始形态、两个人的动作和少量无法由用户指定的自然变化。

一棵树对应一个永久链接。链接就是这棵树，打开就能看到它现在的样子和它是怎么来的。没有分数、没有输赢、没有结束。

## 2. 目标与非目标

**目标**

- 验证"异步、微小、延迟反馈"的双人互动是否能让两个人持续回来。
- 验证只靠一个动作（剪）能否产生两个人之间的互动感，而不需要文字沟通。
- 建立一个能确定性回放的世界模型，为时间轴和开屏回放打底。
- 让手机用户第一次打开就能看见一棵有特点、可以动手修剪的幼树。
- 通过调试模式在几分钟内验证几天的生长、两人的操作和异常情况。

**非目标**

- 封存、多棵树、画廊、"下一盆"之类的流程。一个链接只有一棵树。
- 树的衰老和死亡。树可以长满、静止，但不会坏。
- 逼真的植物模拟、蟠扎、换盆、季节、活力。
- 通知、普通用户账号、社交分享平台接入、原生手机 App。
- 剪后撤销、种子发芽阶段、用户选择随机种子或精确指定未来树形。

## 3. 用户与场景

两个彼此熟悉的人，多半是一对伴侣或好友。大部分时候通过手机链接进入，单手触摸操作；桌面浏览器作为补充。他们不在同一时间打开，一个早上看、一个晚上看，中间隔十几个小时甚至几天。每次打开一两分钟：先看树从最初幼树长到现在，再看一眼现状、也许剪一刀，然后走。

所以打开第一眼就要给信息，一次操作几秒内完成，不在时世界要继续走，回来时要有"发生了事"的感觉，而且不靠文字解释——两个人有自己的沟通渠道，这里只负责让他们看到。

## 4. 设计原则

**延迟反馈是题眼。** 剪一刀后的新形态要等新芽长出来才显现。不预览未来长成什么样；选中时必须明确显示本次将剪掉的范围，成功后立即反馈。

**动作少而重。** 每人每滚动 24 小时一刀，先选中、再确认，提交成功后不可逆。不做撤销。稀缺让每一刀值得想一下，"不剪"也是一种表达。

**树是自己的。** 世界按真实时间走，两个人不在时它照样长。不惩罚缺席，但缺席可见。

**先看变化，再做决定。** 每次进入树页面，先回放从初始幼树到现在的整个过程，包括双方的剪枝与回芽；可以跳到现在。用视觉呈现变化，文字负责时间、归属和操作提示。

**随机但不重抽。** 每棵树出生时不同，后续生长也有微小偏差；用户不能指定偏差。相同历史在任何设备、任何一次回放中都必须一致。

**手机优先。** 关键操作无需悬停，点中枝条不直接剪断；选择、取消和确认都能用手指可靠完成。

**历史与现状同等重要。** 时间轴是核心界面，不是附属功能。

**链接就是树。** 没有登录、没有列表。谁有链接谁就能看，谁想养谁就输个名字。

## 5. 核心循环

```
打开链接 → 回放初始幼树至现在 → 看现在的树 → 选枝 → 确认剪下 → 离开
                                  │                    ↓
                                  └─ 也可以不剪    几小时后回芽，几天后改变树形
```

没有终点。树长满后进入静止，两个人的每一刀都在改它的形状，什么时候不剪了它就停在那里。

## 6. 机制详述

### 6.1 链接与身份

第一次打开根链接，输入名字，点"领一盆树"，客户端生成一个随机 UUID，经 API 创建成功后跳到 `/t/<treeId>`，这就是这棵树的永久地址。服务端同时确定这棵幼树的随机种子和初始生长年龄，出生时已有至少两根可选、可剪的非主干枝。用户不需要等种子发芽。把链接发给另一个人，对方先看回放，想剪时再输入名字加入，就是两个人的树。刷新和直接访问这个地址都由 Render 返回同一个前端页面。

名字和稳定的参与者 ID 存在 Neon 的参与者表，本机按树保存自己的参与者 ID 和名字。输入名字就登记加入，不必等到第一次剪枝；两端因此都能看到图例。颜色按服务端记录的加入顺序分配：第一个暖色，第二个冷色，之后使用固定扩展色板。图例常驻，自己的名字后标"（你）"。

不做账号、不做所有者权限。有链接的人都能看，也能输入名字加入并剪枝。这一版信任链接和名字：同一棵树内，名字经首尾去空白和 Unicode NFC 规范化后相同，就恢复同一个参与者 ID；拒绝空名字，长度为 1–32 个 Unicode 码点，大小写不同视为不同名字。重名的两个人需要自行区分名字，改用新名字会成为新参与者。名字恢复不是身份认证，MVP 不防冒名或换名绕过额度；服务端仍校验参与者属于这棵树，以及该参与者的冷却时间。

### 6.2 初始幼树、生长与自然随机性

树是递归分叉结构，每根枝有自己的出生时刻。`planted_at` 表示用户领到树的时刻，也是时间轴的起点；初始树形相当于模型已生长 16–20 小时，具体年龄由服务端随机种子决定并保存为 `initial_age_ms`。主干模型出生时刻为 `planted_at - initial_age_ms`。这段出生前的模型年龄只用来生成幼树，不向用户播放种子发芽，也不计入“你们养了几天”。

| 参数 | 基准值 / 范围 | 说明 |
|---|---|---|
| 初始模型年龄 | 16–20 小时 | 出生就有至少两根明显可选的侧枝 |
| 枝长足时间 | 12 小时 × 节奏系数 | 长度从 0 到满，先快后慢 |
| 第一根子枝 | 父枝出生后 5 小时 × 父枝节奏系数 | 接在枝梢，偏一侧 |
| 第二根子枝 | 父枝出生后 11 小时 × 父枝节奏系数 | 接在七成处，偏另一侧 |
| 每枝节奏系数 | 0.9–1.1 | 每根枝固定，影响这根枝的长足与分叉时刻 |
| 最大深度 | 7 | 主干为第 0 层，共 8 层 |
| 每层长度衰减 | 0.76 | 本枝最终长度再乘 0.92–1.08 的扰动；不改变后代的基准长度 |
| 每层粗度衰减 | 0.78 | 再乘生长进度 |
| 基准分叉夹角 | 左右各 30–45° | 按树的种子确定基准形态，每枝再偏差 ±5° |
| 主干初始倾斜 | ±8° | 出生时已确定，之后不突然改变 |
| 回芽等待 | 4 小时，偏差 ±30 分钟 | 每个断口独立确定，只改变微小节奏 |

初始随机性体现在主干倾斜、分叉角、枝长和初始生长年龄；后续随机性体现在每根新枝的生长速度、轻微方向偏差和回芽等待时间。每层两根子枝交替偏向左右，所有枝有轻微向上牵引，叶团只画在没有子枝的枝梢，随生长进度变大。随机偏差在连续生长中显现，不让已长成的枝突然跳动、断裂或死亡，也不额外生成第三根子枝。

不剪时，目标是领到后约三天长完整。按上述范围，从模型主干出生至完全长足的时间介于 `89 × 0.9` 与 `89 × 1.1` 小时之间，再扣除 16–20 小时初始年龄，即领到后约 **60.1–81.9 小时（2.5–3.5 天）**。最多 255 根枝、128 个末端。长满后自然随机性不再无限增加复杂度，新的结构变化来自剪和回芽。

每棵树创建时由服务端生成一次高熵 `seed`。生长中的每个随机量由 `sample(seed, growthKey, property)` 独立推导；`growthKey` 是由枝条生长谱系确定的稳定标识，属性使用不同名称，例如 `growthTempo`、`angle`、`length`、`budDelay`。不能依赖递归遍历时的抽签顺序。普通用户没有选 seed、重抽当前树或调整扰动的入口，刷新、重试和回放不会重抽。这里的“无法控制”指普通产品交互不提供控制，不承诺对能读取模型与 seed 的技术用户隐藏未来。

回芽的随机取样标识由被剪枝及其固定子枝位置推导，不使用客户端可自选的请求 UUID 作为随机来源。事件 UUID 仍用于唯一标识新芽；取样标识与事件 ID 分离，避免仅仅换一个请求 ID 就换一次生长结果。

### 6.3 剪

剪枝必须经过两个独立动作：先点一根枝选中，再点底部的“确认剪下”。选中时高亮该枝及所有会一起移除的后代，显示断口位置；底部提示“将剪掉高亮部分，剪下后不能恢复”，同时提供“取消”。再次点击同一根枝不会提交；点击空白或取消清除选择，点另一根则切换选择。主干不能剪，选中阶段不占用每日额度。

选择框展示当前删除范围，不展示未来生长结果。拖动画布、缩放、操作时间轴或回放都不能触发剪枝。若确认前同步发现目标已消失，清除选择；若高亮范围发生变化，更新范围并提示用户重新检查，不能沿用旧确认直接提交。

服务端确认成功后，该枝及后代掉落并从当前树移除。断口留一小截红色的茬，三天内淡去。剪后约 4 小时（±30 分钟），父枝在断口附近冒一个新芽，方向偏离被剪的那根，往另一侧长，再叠加轻微角度扰动。新芽是普通的枝，会分叉、可以被剪、被剪后再回芽。断口与新芽短暂保留对应操作者的颜色线索，帮助用户认出因果。

每人每滚动 24 小时一刀，以服务端成功保存的上一刀为准。点“确认剪下”时生成事件 ID；提交过程中按钮显示“正在剪下”，禁止重复提交，未确认结果前不切换目标。只有 API 确认成功后才移除枝条并消耗额度；请求结果不明时，用同一个动作 ID 重试确认。剪过之后显示还要等几小时。成功后没有撤销，也不提供五秒恢复窗口。

### 6.4 看

树每分钟根据模拟时间更新一次。点选枝条后，在底部面板显示它何时长出、是否长足；桌面可以额外支持悬停，所有信息都能通过触摸或键盘访问。手机支持双指缩放和放大后的拖动画布，提供“看整棵树”复位入口。

时间轴在树下方，从初始幼树拖到现在，任何时刻的树形都能看，剪枝事件带操作者颜色和可点选刻度。相近刻度聚合，展开后可逐个查看；另有“上一刀／下一刀”操作，不要求手指精确拖到某一秒。历史状态与回放状态不能剪，点“回到现在”并完成同步后才允许选择和确认。

### 6.5 打开时的回放

每次进入树页面（首次受邀打开、刷新或重新打开链接），完成首次同步后自动播放一次 **从 `planted_at` 的初始幼树到当前快照时刻** 的完整历史。包括自然生长、双方所有成功的剪枝、断口与回芽；不再以“上次离开”作为回放起点，也不排除自己的剪枝。新领取且几乎没有历史的树，仅展示约 0.5–1 秒的幼树入场，不虚构出生前的发芽过程，随后即可剪枝。

默认总时长 6–12 秒，按历史长度压缩时间，无变化区间快速越过；通常一两刀时，每刀短暂停留约 0.3–0.5 秒。剪枝用操作者的颜色亮起，整段枝连叶掉落，然后继续生长。长历史仍遍历全部事件，不保证自动播放时能逐刀看清；提供暂停、慢速、再看一遍和始终可点的“跳到现在”，用户可在时间轴逐刀检查。手动慢放不受 12 秒上限限制。时间指示持续显示从“刚领到”走向“现在”，避免被误认为树正在实时快速生长。

回放开始时固定事件快照和结束时刻，期间收到的新事件先排队，结束或跳过后合并到当前视图，不在中途重置回放。播放与历史查看时禁用剪枝；跳过必须落到最新已同步状态，不能停在中间历史帧。页面短暂切到后台再回来只同步到现在，不自动从头再播；用户可主动重播。

系统设置了“减少动态”的用户，开屏改用初始幼树与当前树的静态对照，以及可逐步查看的剪枝刻度，不播放旋转掉落和快进动画。完整时间范围和事件仍可访问。

不再保存“上次离开时刻”来决定开屏行为。同步游标只是当前已加载事件缓存的位置，与回放播放进度分开；回放、跳过或拖动时间轴都不能推进网络同步游标。浏览器没有完整事件缓存时必须从头获取日志，不能仅凭本机保留的旧序号请求增量。

## 7. 界面

手机竖屏单页，从上到下；树、时间轴和当前主要操作优先进入首屏，规则说明放在可展开区域：

```
我的盆栽
领来就是一棵小树，几天后长成。你们俩每 24 小时最多各剪一刀。

┌──────────────────────────┐
│                          │
│         （树）            │
│                          │
│        ▁▁▁▁盆▁▁▁▁          │
└──────────────────────────┘
状态一句话：你们养了 2.1 天。点一根枝看看。
● 阿范（你）  ● 小李

─────●──────────────────── 时间轴
刚领到                          现在

（选中时的底部面板）
这根枝已长足。将剪掉高亮部分，剪下后不能恢复。
     [取消]          [确认剪下]

说明文字（规则）
```

状态行只说树现在怎么样、你现在能做什么；回放时间、枝条详情和按钮状态按交互变化。年龄从领取时刻开始计算，不计出生前的模型年龄。

- 根页面：给自己起个名字 →「领一盆树」
- 回放中：从刚领到，看到现在 →「跳到现在」
- 尚未加入：可以先看看。想一起养，告诉我你是谁
- 你们养了 N 天。点一根枝看看
- 选中：将剪掉高亮部分，剪下后不能恢复 →「取消」「确认剪下」
- 提交中：正在确认这一刀，请稍等
- 你们养了 N 天。N 小时后可以再剪
- （拖时间轴时）X 时刻的样子

错误直说发生了什么和怎么办：这根枝已经不在了，选另一根；还要等 N 小时才能剪；正在确认刚才那一刀，请稍等；暂时连不上，稍后重试。网络超时不等于剪枝失败，重试沿用原动作 ID；未完成首次同步时不允许剪枝，不显示成空盆或不存在的树。

### 7.1 手机交互要求

- 优先验证 360–430 CSS 像素宽的竖屏，兼容更窄的 320 像素视口；不出现页面横向溢出，底部确认面板避开系统安全区和软键盘，不遮住选中的断口。
- 确认、取消、跳过、缩放复位及时间轴滑块的触摸区域至少 44 × 44 CSS 像素。细枝绘制透明命中区域；密集处命中多枝时只进入候选选择，配合高亮和放大辨认，绝不猜测后直接剪下。
- 手指滑动超过手势阈值按拖动处理，不触发点选；双指缩放不触发剪枝。缩放和移动限制在画布范围内，画布外仍可正常滚动页面。
- 底部面板贴近拇指区域，选枝与确认按钮位置分离；长按和双击都不作为隐藏的直接剪枝捷径。桌面点击同样遵守两步确认。
- 归属除颜色外还可查看名字，选中范围使用轮廓强调；按钮有可读标签，时间轴和候选枝支持键盘与辅助技术操作。减少动态使用第 6.5 节的静态替代。
- 回放优先保证中端手机流畅；高亮范围和按钮反馈应即时响应。桌面沿用同一功能，利用更宽视口放大树，不引入只有桌面才能用的规则。

## 8. 数据模型

使用 Neon 托管的 PostgreSQL，应用通过参数化 SQL 访问。保存树元数据、参与者和成功的剪枝事件，不保存树形、枝条几何或逐分钟生长状态。SQL 迁移文件纳入仓库，以下为 MVP 表结构：

```sql
CREATE TABLE trees (
  id uuid PRIMARY KEY,
  planted_at timestamptz NOT NULL,
  model_version text NOT NULL,
  seed text NOT NULL CHECK (seed ~ '^[0-9a-f]{32}$'),
  initial_age_ms integer NOT NULL
    CHECK (initial_age_ms BETWEEN 57600000 AND 72000000),
  last_cut_seq bigint NOT NULL DEFAULT 0 CHECK (last_cut_seq >= 0)
);

CREATE TABLE participants (
  tree_id uuid NOT NULL REFERENCES trees(id),
  id uuid NOT NULL,
  name text NOT NULL CHECK (char_length(name) BETWEEN 1 AND 32),
  ordinal integer NOT NULL CHECK (ordinal > 0),
  joined_at timestamptz NOT NULL,
  PRIMARY KEY (tree_id, id),
  UNIQUE (tree_id, name),
  UNIQUE (tree_id, ordinal)
);

CREATE TABLE cuts (
  tree_id uuid NOT NULL REFERENCES trees(id),
  seq bigint NOT NULL CHECK (seq > 0),
  event_id uuid NOT NULL,
  participant_id uuid NOT NULL,
  branch_id text NOT NULL,
  expected_seq bigint NOT NULL CHECK (expected_seq >= 0),
  cut_at timestamptz NOT NULL,
  PRIMARY KEY (tree_id, seq),
  UNIQUE (tree_id, event_id),
  FOREIGN KEY (tree_id, participant_id)
    REFERENCES participants(tree_id, id)
);

CREATE INDEX cuts_participant_latest
  ON cuts (tree_id, participant_id, seq DESC);
```

- `trees.id` 是链接中的随机 UUID，不使用可枚举的自增编号。领取幼树、生成 seed 和加入第一位参与者在同一事务提交；`ordinal = 1` 的参与者就是最初领树的人。重复创建请求返回原树，不重新抽 seed。
- `seed` 是服务端生成的 128 位随机值，以 32 位十六进制文本保存。`initial_age_ms` 由 seed 与模型版本确定并保存。普通创建 API 不接受客户端指定这两个字段；读接口返回它们以便客户端重建同一棵树。
- `model_version` 冻结这棵树的初始化规则、生长参数、随机属性名称与采样算法。新版本只影响新领的树，旧版本实现继续保留，以保证历史不变。
- `last_cut_seq` 是每棵树已提交的最后一刀序号，用于排序、增量同步和分配下一序号，不代表树的生长进度。参与者的加入顺序也在锁住树记录后分配。
- `cuts` 只追加成功事件；失败操作不进入世界历史，也不消耗额度。客户端在确认剪下时生成 `event_id`，重试必须复用。`expected_seq` 记录用户确认时看到的最后剪枝序号。相同 ID、相同参数返回原结果；相同 ID、不同参数返回冲突。
- 所有正式业务时间由数据库产生，统一截取到毫秒精度，API 返回 UTC 时间；客户端不能指定领取或剪枝时间。剪枝时间不得早于已提交的上一刀，同一毫秒内按 `seq` 排序。出生前各枝的时间由初始年龄和模型推导，不作为客户端提交的业务时间。

普通枝 ID 是从根开始的路径，如 `0.1.0`；回芽的枝 ID 为父枝 ID 加 `.b` 加剪枝事件的完整 UUID。同一事件总生成同一个芽，不依赖本机时钟或短哈希碰撞概率。每根枝另有用于随机采样的 `growth_key`：初始枝使用固定路径，普通子枝由父枝的 key 加固定子枝位置推导，回芽由被剪枝的 key 加 `regrowth` 推导；该 key 不包含请求 UUID。回芽替代被剪枝的子枝位置，深度仍为父枝深度加一，原枝不再自动长回；父枝被剪掉后，其尚未出生的芽也取消。

本机保存每棵树的参与者 ID、名字，以及尚未确认的请求 ID 与参数。当前事件缓存和同步游标在内存中配套维护；重新打开页面从头获取日志。冷却时间从服务端事件计算，清缓存不会清除已有参与者的额度记录。不存普通用户账号、密码或登录会话。开发者沙盒及调试鉴权另见第 9.5 节。

## 9. 架构与确定性

### 9.1 部署

一个 Render Web Service 运行 Node.js + Express，同时提供 HTML/CSS/JavaScript 静态文件与同域 JSON API；Neon PostgreSQL 是唯一持久化存储。前端使用原生 ES modules，前后端共享生长模型模块，MVP 不引入前端打包流程。

```text
浏览器（SVG、时间轴、回放）
          │ 同域 HTTPS / JSON API
          ▼
Render Web Service（Node.js + Express）
          │ 参数化 SQL / TLS
          ▼
Neon PostgreSQL（trees、participants、cuts）
```

- Render 从代码仓库部署；安装命令为 `npm ci`，启动命令为 `npm start`，监听 `0.0.0.0` 和 Render 注入的 `PORT`。`GET /healthz` 提供轻量存活检查，数据库连接另做部署验证。
- Neon 的带 TLS 的 pooled connection string 配置在 Render 服务端环境变量 `DATABASE_URL`，不进入前端、仓库或响应日志。Node.js 使用 `pg.Pool`，MVP 先将应用连接池上限设为 5，Render 与 Neon 尽量选择相近区域。
- SQL 迁移使用独立命令 `npm run db:migrate`，记录已执行版本；部署流程先完成兼容迁移再发布代码，不由每个请求或多个进程同时迁移。
- Render 本地磁盘不保存业务数据，重启、重新部署或扩展实例后仍从 Neon 读取。应用不使用内存锁维护剪枝额度。
- 无生长定时任务、无常驻后台模拟。Render 或数据库暂时休眠不会停止树的时间；下次读取时根据事件和当前时间重建。

Render 免费 Web Service 会在连续 15 分钟没有入站流量后休眠，下一次访问可能等待唤醒。免费实例适合技术验证；两周体验测试优先使用不会自动休眠的付费实例，避免冷启动影响“一两分钟看一眼”的场景。Neon 如启用计算休眠，也要在验收中实测首次查询延迟。参见 [Render 免费实例说明](https://render.com/docs/free)、[Render Web Service 文档](https://render.com/docs/web-services) 与 [Neon 连接池文档](https://neon.com/docs/connect/connection-pooling)。

### 9.2 API 与同步

| 接口 | 用途 |
|---|---|
| `POST /api/trees` | 提交 `treeId` 与名字，服务端生成 seed 和初始年龄，原子创建树和第一位参与者；同 ID、同规范化名字重试返回原树，不同参数返回冲突 |
| `POST /api/trees/:id/participants` | 输入名字加入或恢复参与者，返回稳定 ID 和加入顺序 |
| `GET /api/trees/:id?after=<seq>` | 返回树元数据、完整参与者列表、序号大于 `after` 的剪枝事件、响应快照中的 `lastCutSeq` 和 `serverNow`；首次省略 `after` 获取全部事件 |
| `POST /api/trees/:id/cuts` | 提交 `eventId`、`participantId`、`branchId`、`expectedSeq`；服务端校验并返回已提交事件及 `nextCutAt` |

读接口中的树元数据、参与者与事件来自同一个只读一致性快照。事件按 `seq` 升序返回，客户端按序合并并用事件 ID 去重。MVP 全量历史规模较小，首次打开一次取全；后续只取增量。用户输入按文本渲染，API 校验名字和 ID、限制请求体大小，SQL 不拼接用户输入。动态 API 响应不使用共享缓存。

MVP 使用轮询：首次打开、页面重新可见、网络恢复和操作完成后立即同步；前台空闲时每 15 秒同步一次，后台暂停，失败时逐步延长重试间隔。每次只保留一个同步请求，写入响应不能让游标越过尚未拉取的事件；游标只推进到本地已连续合并的最后序号。暂不引入 WebSocket、SSE 或数据库订阅。

这是一种最终一致的异步体验：通常最多约 15 秒后看到另一端的新动作，网络异常时可能更久。浏览器用最近一次 `serverNow` 与单调计时器估计当前时间，切回前台重新校时；是否能剪仍以服务端为准。

### 9.3 确定性与渲染

整棵树是纯函数 `build({ modelVersion, seed, plantedAt, initialAgeMs }, cuts, now)`：先生成 `plantedAt` 时已有的幼树，再按事件序号将生长推进到每一刀的时刻、应用该刀，最后推进到 `now`；忽略 `cut_at > now` 的事件。`now < plantedAt` 时返回“尚未领取”，不生成可交互的出生前历史。前端回放、服务端校验与调试沙盒使用同一份模型代码。

业务随机通过 `sample(seed, growthKey, property)` 生成固定的 `[0, 1)` 值，再映射到第 6.2 节的范围。模型不读取系统时钟或调用 `Math.random()`，不使用全局随机流，因此剪掉一边不会让另一边的随机参数重排。随机采样结果不需要逐条写入数据库，树元数据与动作日志足以复现。用于掉落的装饰动画不能反过来改变世界状态。

相同版本、seed、初始年龄、事件集和时间输入应产生相同的枝条结构和几何数据；在线两端可能短暂处于不同同步进度，不能承诺每个瞬间画面严格一致。时间轴和回放都从日志重建，不需要保存每一帧或后台持续更新树。

渲染使用 SVG。成熟树最多 255 根枝，另有叶团、点击区域与动画节点，因此不再假定 DOM 节点少于 200。静态状态每分钟更新一次；回放通过 `requestAnimationFrame` 推进模拟时间。掉落子树保留在独立动画层，正常树形重绘不能销毁正在掉落的节点。长历史下的重建与回放性能通过验收测试决定是否需要缓存。

### 9.4 写入事务与并发

剪枝请求使用 `pg.Pool` 借出的同一连接执行完整事务，流程为：

1. `BEGIN`，对该树执行 `SELECT ... FOR UPDATE`；同一棵树的写入串行化，不同树互不阻塞。
2. 检查 `(tree_id, event_id)`：若已存在且参与者、枝条和 `expectedSeq` 参数相同，直接返回原事件；参数不同则拒绝。幂等检查优先于版本和冷却校验。
3. 检查 `expectedSeq` 是否等于当前 `last_cut_seq`。若不同，返回冲突，客户端先同步最新树形再让用户重新选中或确认，不自动重提。拿到行锁后读取数据库当前时间，校验参与者属于该树、距上一刀至少 24 小时，再用完整已提交历史重建当前树，验证目标枝存在且不是主干。业务时间使用锁后的数据库时间，而不是客户端时间或事务开始时间。
4. 分配 `last_cut_seq + 1`，写入剪枝事件并更新树的最后序号，`COMMIT` 后才向客户端确认成功。任何校验失败都回滚，不写事件，不扣额度。

两人从同一版本同时确认时，先提交的一刀成功，另一刀因版本落后被拒绝且不消耗额度；即使两根枝互不包含，也先同步并重新确认，确保用户知道自己确认的树形。若目标还存在，可以生成新事件 ID 再确认；若已被对方剪掉，提示“这根枝已经不在了”。先剪祖先会使后代目标失效；先剪后代后，另一人可在最新版本重新确认剪祖先。同一参与者双标签同时提交不同动作也不能绕过 24 小时限制。

请求超时但事务可能已提交时，客户端保留原 `eventId` 和参数，用同一 ID 重试直至确认；不为重试生成新动作。加入参与者也先锁住树记录，再查找规范化名字或分配加入顺序，避免并发加入时颜色不稳定。

### 9.5 Debug 上帝模式

提供独立 `/debug` 页面，供开发者快速验证模型和手机体验。普通用户页面没有入口。默认在本地开发环境启用；需要手机远程调试时，在独立 Render 预览服务启用 `DEBUG_ENABLED=true`，通过服务端验证环境变量中的 `DEBUG_ACCESS_TOKEN` 后签发短期、HttpOnly 的调试会话 Cookie，HTTPS 下使用 Secure 和 SameSite=Strict。token 通过输入框提交，不放在 URL 或前端源码中；预览服务的 token 校验接口应限制尝试频率。正式服务禁用调试页面与接口，不能通过查询参数开启。普通用户免登录不代表调试模式免鉴权。

上帝模式操作独立沙盒，页面常驻“调试沙盒／模拟时间”标识。可以加载一棵真实树的元数据和日志作为只读副本，但沙盒操作绝不调用正式剪枝 API，也不写回正式 Neon 数据。刷新或重置沙盒仅影响调试状态；可导出 JSON 用于保留复现场景。

| 控制 | 行为 |
|---|---|
| 时间控制 | 暂停；以 1×、60×、3600× 速度推进；跳过 1 小时、4 小时、24 小时；定位到指定模拟时刻 |
| 初始树控制 | 输入或重抽 seed，设置 16–20 小时初始年龄，立即查看出生枝条；只影响当前沙盒 |
| 双人模拟 | 切换参与者 A/B，查看双方颜色、额度与下一次可剪时间 |
| 规则开关 | 默认执行正常规则；可显式开启忽略冷却，但仍保留主干禁剪、选中与确认，并醒目标记规则已放宽 |
| 参数调节 | 调整生长时间、最大深度、扰动强度；标记为实验配置，不覆盖正式模型版本 |
| 回放检查 | 重新播放全部历史、暂停逐帧、逐刀跳转，显示初始状态、断口和回芽的对应关系 |
| 枝条检查 | 查看枝 ID、growth key、出生/长足/分叉时刻、深度、随机属性与受影响子树大小 |
| 异常模拟 | 模拟延迟、断网、写入成功但响应丢失、重复响应、版本冲突和另一参与者剪枝 |
| 复现场景 | 导入/导出模型版本、seed、初始年龄、参数覆盖、参与者、事件日志和模拟时刻；提供“恢复初始沙盒” |

调试中时间回拨默认只查看历史，禁止在过去写入。要从过去试另一种剪法，使用“从此刻分支”：复制为新的本地沙盒并截断未来事件，不修改原沙盒或真实树。修改 seed、初始年龄或生长参数时新建沙盒并清空动作历史，保留原场景供对照，避免把旧枝 ID 的动作套到新树形上。忽略冷却产生的实验事件注明调试来源，不作为正常用户行为数据。导入 JSON 校验结构、大小和事件顺序，不执行其中的代码。

沙盒时间通过可注入的时钟传入共享模型；时间倍速同时影响生长和沙盒中的 24 小时冷却，不能把浏览器系统时间改动当成快进功能。前端网络故障模拟用于验证交互，真实数据库锁、并发和幂等仍须通过隔离测试数据验证，不能用沙盒代替。

## 10. 边界情况

- 一方长期不来：树继续长，另一方照常剪；重新打开时回放从初始幼树到现在的全部历史，默认压缩到 6–12 秒。长历史可以暂停、慢放或逐刀查看，不承诺默认速度下看清每一刀。
- 树长满七层且两人都不剪：树静止。这是正常状态，不是问题。
- 时间轴最早到领取幼树的时刻，不开放出生前的种子阶段；调试器查看更早时间时显示“尚未领取”。
- 本机记录丢了（换浏览器、清缓存）：仍先回放完整历史；重新输入同一名字即恢复服务端参与者及冷却时间，树的 seed 和初始形态不会变化。
- 打开一个不存在的树 ID：API 明确返回 404 后显示"没有这棵树"，给回根链接。网络失败或服务唤醒不能误判为不存在。
- 第三个人拿到链接：能看能剪。MVP 不防。
- Render 重启或重新部署：Neon 中已提交的数据不受影响；客户端重新拉取事件，未确认的动作使用原 ID 重试。
- 数据库不可用：不接受新剪枝；已加载页面可显示已同步历史推算的树形，并提示暂时无法同步。恢复连接后以服务端日志校正。
- 回放时有另一刀到达：先完成当前固定快照的回放，再合并到现在；不重复从头播放，不让用户对旧树形直接确认剪枝。
- 手机误触或手势冲突：点选不扣额度；滑动、缩放、取消和切换候选枝都不会提交，只有独立确认按钮能提交。
- 调试沙盒加载真实树：复制后的快进、改 seed、连续剪枝和重置均不影响原树；正式 API 不接受调试时间、seed 覆盖或忽略冷却参数。

## 11. 未决问题

**一天一刀的"一天"。** 滚动 24 小时跨时区没问题，但会固化成"她早上剪、我晚上剪"的错开节奏。先用滚动，观察一周。

**确认交互的准确性。** 两步确认且不撤销已定。试用时观察小屏密集枝条是否容易选错，优先调整命中范围、候选切换与高亮，不用剪后撤销弥补。

**每次开屏全程回放的长度。** 全程回放已定，观察用户是否频繁跳过，以及 6–12 秒内能否看懂关键变化；可调节节奏和事件停留时间，保留手动慢放。

**随机幅度。** 先按本版范围实现，观察不同树是否有可辨认差异、微小偏差是否掩盖了剪枝的影响。调试可以比较不同 seed，正式旧树不因参数调整重写历史。

**回放里掉落的枝显示什么。** 现在显示剪之前的完整子树，看得清损失；另一种只显示断口和之后的新芽，更含蓄。等真用一周再定。

**七层封顶后的静止。** 树长满后只剩剪和回芽的博弈，可能会觉得"没东西了"。这是有意的极简，但如果两周后确实因此不再打开，再考虑让树能持续变化。

## 12. 怎么算成功

两周内，两个人在没有任何提醒的情况下各自在不同日期主动回来，累计打开至少十次。至少有一次，一个人看完回放后出于好奇去问另一个人"你为什么剪那根"。拖时间轴回看时能认出哪几刀是转折点，并能把至少一次回芽与之前的剪枝对应起来。因选错、不同步或被误导引起的追问不算成功信号。

大部分试用在手机完成。首次使用者应能在一分钟内完成看树、选枝、检查范围和确认剪下，或明确选择不剪，不需要等待幼树长出第一根枝。记录开屏回放是否看完或跳过、选枝是否顺利、是否理解确认不可逆；可通过试用观察和简短访谈收集，不要求先建设完整分析系统。调试沙盒和开发者操作不计入留存或体验结果。

如果一周后都不再打开，最可能的原因按顺序是：树变化太慢看不出区别、一刀的效果看不出和自己有关、没有理由回来。分别对应生长参数、回芽可见性、回放，是下一版优先改的地方。

## 13. 路线

**MVP（本文）**：链接即树、随机初始化幼树、几天长成、轻微自然随机性、手机选枝与确认剪下、回芽、时间轴、全程开屏回放、Debug 上帝模式。

**实现顺序**：先实现带 seed、初始年龄和可注入时钟的共享模型，同时做最小调试沙盒；再打通 Render 页面/API、Neon 迁移、领取幼树、事务剪枝和双端同步；随后完成手机两步确认、完整时间轴与开屏回放；最后补齐调试面板、异常模拟和手机验收。沙盒与正式界面复用模型和剪枝交互组件，避免两套实现漂移。

**进入两周试用前的技术验收**：

- 多组 seed 下，出生即有至少两根视觉上可辨认、触摸可选的非主干枝；不同 seed 初始形态有差异，同 seed、模型版本和初始年龄可复现。
- 两个浏览器（至少一台手机）打开同一链接，能看到相同参与者、事件和指定历史时刻的树形，包括相同自然随机偏差；在服务正常、网络通畅时，前台轮询通常在 15 秒加请求耗时内同步新动作。
- 同一事件重复提交只产生一条记录；同 ID 换参数被拒绝；模拟提交成功但响应丢失，重试能恢复原结果。
- 同一参与者多标签同时剪、双方剪同一枝或祖先／后代枝，均符合第 9.4 节规则；旧版本确认要求重新检查，失败不消耗额度，超时重试不会再次要求确认已经成功的动作。
- 人为修改设备时间不能提前剪枝；服务重启、页面刷新和数据库短暂不可用后，历史与额度仍可恢复。
- 多组 seed 的无剪枝生长计算验证领取后 60.1–81.9 小时内长足、255 根枝上限，以及剪后 3.5–4.5 小时回芽、父枝被剪后取消回芽；自然随机性不改变未受剪枝影响的另一侧参数，模型升级不改变旧树历史。
- 首次受邀、刷新、重新打开都从初始幼树回放到当前快照，包含自己和对方的全部事件；短暂切后台不重复自动播放，跳过后落到最新状态，减少动态可看完整范围的静态替代。
- 在实际 iOS Safari 与 Android Chrome 验证 320–430 像素布局、软键盘、安全区、候选枝选择、缩放拖动与确认；点选、滑动、双击、取消均不直接剪下，提交成功没有撤销入口。
- 在中端手机实测成熟树和一个月模拟事件的回放，目标稳定达到 30 fps；本地点选高亮目标在 100 ms 内响应。记录网络提交耗时、首次冷启动与正常打开耗时，性能不足优先优化重建和绘制，不能丢失历史事件。
- Debug 可快进跨过成熟、回芽和冷却，切换双方并导出复现 JSON；从过去分支不改原历史，加载真实树后任意沙盒操作不改变 Neon 数据。正式环境访问调试入口、接口或提交调试覆盖字段均不能获得调试权限。

**之后再考虑**：意图标记（剪之前先标一根枝给对方看）、把生长模型换成芽活力竞争、蟠扎与季节。

## 附录 A · 生长算法候选

**L-system**（Lindenmayer；Prusinkiewicz, *The Algorithmic Beauty of Plants*）。规则驱动的递归替换，适合确定性回放。简单分叉模板需要额外定义剪后反应，但 L-system 本身可以表达休眠芽因剪枝被激活，并非天然不支持剪枝反应。本文规则模型借鉴递归分叉思想。[剪枝响应示例，§8.3.1](https://algorithmicbotany.org/papers/handbook.95.pdf)。

**Space colonization**（Runions et al., 2007）。在树冠空间分布吸引点，将点分配给影响范围内最近的枝节点，枝条朝这些点的合成方向生长，并移除已占据区域内的吸引点。适合生成树冠骨架。剪枝要移除枝条，再另行定义吸引点恢复与新芽规则；删除吸引点只是改变生长目标，不等于剪掉已有枝条。[原论文](https://algorithmicbotany.org/papers/colonization.egwnp2007.html)。

**芽自组织模型**（Palubicki et al., 2009, SIGGRAPH）。每个芽有活力值，顶芽压制侧芽，按光照和资源竞争。剪掉顶芽后侧芽自然释放，回芽、分枝细化、越掐越密都是涌现的。最贴生理，是之后换模型的首选。

**管道模型 / 达芬奇法则**。父枝截面积等于子枝之和，粗度是叶量的历史积分。用来算粗细和收尖。

**蟠扎**。枝有自然角度，铝丝给目标角度，随时间蠕变定型，拆早了回弹。一阶低通滤波器即可。

**算法评审原型**：见 [盆栽生长算法研究与 MVP](./盆栽生长算法研究与MVP.md)。该原型比较二维简化芽竞争与规则分叉，供树形和剪后反应评审；尚未替换本文正式方案或接入 Neon。
