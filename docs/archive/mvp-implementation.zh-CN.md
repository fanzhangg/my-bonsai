# 一盆树 · 观察版 Prototype

2026-09-16 更新。本轮收敛为「匿名认领 → 唯一链接 → 观察生长」，替代上一版双人照料流程。

## 用户流程

- 首页只有盆栽预览、认领按钮和已有树的返回入口，不填写名字。
- 点击认领，服务器生成随机种子、七款树形之一和六套视觉搭配之一，保存为一棵树。
- 每棵树对应 `/t/<UUID>` 唯一随机标识链接，作为用户所说的 hash 链接。不是内容哈希，也不是会随生长改变的地址。保存或复制链接即可再次访问，不需要登录。
- 树页面只显示盆栽和复制链接按钮。不显示树名、参与者、天数、照料说明或剪枝控件。
- 每次打开链接自动用约 4 秒回放初始枝叶展开至服务器当前状态，结束后隐藏进度条。出生时已有训练骨架，不从种子发芽开始；初始枝叶形成过程也纳入回放，刚认领的树不会跳过动画。遵循系统减少动态效果偏好时直接显示当前状态。
- 页面停留期间每 15 秒更新当前生长状态；切回前台同步但不重复回放。
- 剪枝、加入和命名交互已移除。旧 `/join`、`/cuts` API 返回 410，不会写入新事件。历史树和历史事件保留，旧链接可继续打开。

## 生长和时间

沿用 `bonsai-life-1`，冻结的几何与外观依赖位于 `prototype/core/v1/`。认领时的模型时刻是 46 小时，每现实小时推进 0.23 模型小时，初始树冠约 17–70 小时展开完整，依树形而异。

`prototype/playback.mjs` 把初始的 0–46 模型小时和认领后的真实历史压缩到 4 秒，最终帧与 `snapshot(record, serverNow)` 一致。回放不预览未来、不修改创建时间。保留原训练树干、分级枝序、成组叶团、根颈渐宽和全部视觉方案。

树形和微小随机差异由固定种子决定；刷新不会重新随机生成。当前是受造型约束的确定性展开动画，树冠成熟后不会无限扩张，不包含植物生理或环境竞争模拟。

## 作弊模式（原 Debug）

在树的链接末尾加 `?cheat=1`，兼容原 `?debug=1`。首页也支持进入作弊模式，调整后的样本随认领一起保存。

- 调整认领后时间，默认可拖动 0–168 小时；+4 小时、+1 天可继续扩展范围。
- 切换树形、外观、种子，或随机种子。编辑时预览浏览器副本，点击“保存到这棵树”提交。树形或种子变化会清空旧剪枝；仅换外观保留剪枝。原盆器保持不变。
- 重播：从初始枝叶展开到当前调试时刻，约 4 秒。
- 重新载入已保存状态：重新读取服务器记录，丢弃未保存的调整。
- 检查树 ID、算法版本、模型时刻、枝段数、已开始展开的叶团数和播放状态。
- 退出：回到无作弊参数的原链接。离开页面前，若有未保存修改，浏览器会提示。

保存接口 `POST /api/trees/:id/cheats` 接收 `revision`、`preset`、`look`、`seed`、`hours` 和剪枝列表 `cuts`（包含 `id`、`branchId`、相对年龄 `hour`）。服务器校验字段及旁支 ID，将生长起点调整为服务器当前时间减去指定年龄，并同步平移剪枝时间线；保存后正常模式继续随现实时间生长。回退年龄时，未来的剪枝仍保留，到对应年龄才生效。天气、当地时刻和重播不写入树记录。

作弊保存及普通剪枝都会递增 `revision`，旧记录按版本 0 读取。作弊提交的版本过期时返回 409，提示重新载入，避免覆盖其他页面的修改。保存失败时保留浏览器里的修改；网络中断无法确认结果时可以重试，若返回版本冲突则重新载入确认已保存状态。

## 数据与服务

Node HTTP 服务提供静态页面及应用接口：`POST /api/trees` 认领、`GET /api/trees/:id` 读取、`POST /api/trees/:id/cuts` 剪枝和 `POST /api/trees/:id/cheats` 保存作弊修改。普通创建请求只需 UUID，配置由服务器派生；作弊模式可以附带 `cheat` 对象，与创建记录在同一事务中保存。重试保持同一个创建编号，服务器保证幂等。

数据库使用 `bonsai_trees(id uuid PRIMARY KEY, document jsonb NOT NULL)`；PostgreSQL 使用参数化 SQL 和事务锁。旧参与者字段不再返回给浏览器。开发环境未配置数据库时保存到 `data/trees.json`，重启后保持；仅支持单个本地服务进程。

生产环境必须配置 Neon `DATABASE_URL`，不会降级到 Render 临时磁盘。`render.yaml` 已包含构建、启动和健康检查配置。本轮未配置实际 Neon 连接串，尚未上线联调。
