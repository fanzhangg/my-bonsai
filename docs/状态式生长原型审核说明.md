# 状态式生长原型审核说明

原型入口：`/adaptive-growth.html`。使用仓库现有服务启动后访问该路径即可。本次审核服务地址为 <http://127.0.0.1:4174/adaptive-growth.html>，仅提供页面预览，不连接正式数据库。

## 建议审核顺序

1. 选择真柏，点击“剪空下层”。确认上、中层未移动，下层显示等待萌芽。
2. 点击“+1 小时”查看芽点，再点击“+1 天”查看新侧枝；继续“+1 天”看细枝与叶片展开。
3. 打开“查看未修剪对照”，比较同一种子、同一时刻的两种树形。
4. 点击“剪空所有侧枝”，再快进三天。反复剪掉恢复枝，确认仍能继续生长。
5. 开启“细枝修剪”和“只看枝干结构”，剪去二级枝，确认从活父枝重新生成子枝。
6. 切换文人松、榉树，观察各树形的留白和生长方向。自动生长每秒推进两小时，可暂停；撤回恢复上一次手动操作前的完整状态。

状态保存到浏览器本地的独立键 `bonsai-adaptive-review-v1`，不修改认领盆栽。重置和换树均可在当前页面撤回；刷新保留树状态，但不保留撤回栈、自动播放或显示开关。页面关闭时暂停，不按真实离线时间自动推进。

## 本次实现范围

- `prototype/adaptive-growth-model.mjs`：独立状态模型，局部恢复任务、半小时逻辑步进、空间候选评分、稳定随机源、逐代生成、父枝删除与子任务清理。
- `prototype/adaptive-growth.html / .css / .mjs`：独立审核界面，三种树形、圆点修剪、细枝模式、全剪场景、快进、对照与本地保存。
- `tests/adaptive-growth.test.mjs`：局部恢复、100 轮全剪、分段推进、细枝补回、当前占用改变生长方向、保护枝及稳定后停止增枝等验证。

复用当前工作区的 morphology 和 growing-render 作为初始标本及绘制适配，不修改它们。Node.js 24 下完整 `npm test` 通过；浏览器检查了桌面和 390px 手机宽度，以及局部剪空、全剪恢复、细枝修剪和对照功能。

## 原型与最终方案的区别

初始标本仍借用现有主干与一级枝，所有新枝及新后代按当前状态生成。每次只决定一根新枝的曲线；同一根枝的延伸方向在这一代内固定，尚未实现枝梢逐段转向。

本版上、中、下层从初始侧枝着生高度分组，并在支撑枝附近的区间内选择新着生点。只开放真柏、文人松、榉树，不把这种分组直接用于悬崖等树形。枝序最多三级，每个成熟侧枝最多两根直接子枝；不存在无上限增殖。

空间评分目前使用活枝末端间距与画框限制，未做完整的曲线碰撞、光照遮蔽或资源生理模拟。极端种子下的新枝交叉与美术比例需要后续校准。它用于审核“剪法改变后续生成、局部缺枝能恢复”的玩法，不等同于正式引擎的全部质量保障。

尚未接入云端事件记录、旧树迁移、分享/Gallery、浇水或正式剪刀拖动动画；审核确认玩法后再接入。恢复速度为便于观察的原型参数，尚不是最终产品节奏。
