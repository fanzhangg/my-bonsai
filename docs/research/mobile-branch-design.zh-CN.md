# 手机端枝干造型调整方案

研究日期：2026-09-17。状态：已实现 Design System 三树形候选对照，等待用户视觉审核；应用仍使用原枝干方案。前面的参数表为初始研究目标，当前候选实现范围见第 7 节。

目标：关掉叶片后，在手机正常浏览尺寸下仍能读出主干、主要侧枝和二次分叉的走向；七种树形靠枝干就有各自的性格。盆器沿用已审核的原始尺寸 150%，主干与镜头作为第一轮比较的固定条件。

## 1. 当前问题及测量

代码入口为 `morphology.mjs → growth.mjs → growing-render.mjs`，底层骨架来自冻结的 `core/v1/canopy.mjs`。浏览器检查「树形谱系 / 只看枝干」可见：真柏侧枝很快收成细线，榉树末端成为细密毛边，文人松主要剩主干可读。

使用种子 `DESIGN-SYSTEM-01`，成熟进度 `grow(record, 1)` 测量。以下是曲线段数，不是独立长枝数量，也不是所有种子的统计分布。

| 树形 | 全部枝干曲线段 | 主侧枝 primary | 细枝 twig | 末端叶团数 |
| --- | ---: | ---: | ---: | ---: |
| 分层真柏 | 151 | 6 | 138 | 72 |
| 圆顶榉树 | 230 | 7（另有 3 段 bough） | 217 | 112 |
| 文人松 | 87 | 5 | 75 | 40 |
| 直干黑松 | 150 | 6 | 138 | 72 |
| 斜干松 | 150 | 6 | 138 | 72 |
| 悬崖真柏 | 88 | 4 | 76 | 40 |
| 风吹松 | 106 | 5 | 95 | 50 |

关键原因：

1. **侧枝近根部粗，梢部突然变细。** 旧骨架的 primary 多采用固定 `tipWidth:1.5`；形态层将 primary 基部乘以 1.65，但梢部仅乘以 1.2，未建立与整条枝长、母枝和分叉职责对应的连续收分。
2. **侧枝递归缩细过快。** 形态层把子枝限制在连接处母枝粗度的 0.58 以内，再将枝梢限制为自身的 0.72 以内。接在枝尾的后代连续受到这两个限制，宽度上限约按 0.42 倍逐级衰减。不能只把旧宽度统一乘一个系数。
3. **先分布叶团，再反推枝网。** 当前每片冠区生成 8–16 个末端目标，再递归二分连接，得到约 `2N-1` 条 twig 曲线。模型首先服务于填满叶冠，未优先设计裸枝的主次、折返和留白。
4. **代码层级不等于视觉枝序。** `twig.depth=0` 是从 primary 中段伸出的子树首段；榉树还多一层 bough。不能简单把所有 `twig` 一起加粗，或把每个曲线节点都算一阶分枝。

真柏 twig depth 0 的基部宽度为 0.56–1.62 模拟单位，depth 1 为 0.24–0.64，depth 4 仅 0.02–0.05。按应用 390px 宽屏、374px 画布、640 单位 viewBox 估算，缩放约 0.584，第一组只有约 0.33–0.95 CSS px，最细组约 0.01–0.03 CSS px。此处是代码与布局推算，不是移动真机测量；高 DPR 不会补回视觉层级。

## 2. 设计方向：少量有重量的枝线，清楚的不对称分叉

统一称谓：主干记为 L0；直接承接主干的主要侧枝为 L1；从 L1 发出的结构侧枝为 L2；末梢为 L3；更细分叉为 L4+。一条枝上的连续曲线段不重复增加枝序。榉树的粗大 bough 属于 L1，后续 primary 在视觉上可能属于 L2，须按连接结构判断。

第一轮建议采用以下美术起点。数值是待预览校准的项目参数，不是盆景行业标准；像素目标指 390px 手机中成熟树的主要可见部分，不包括最后收尖的极短端点。

| 层级 | 结构职责 | 粗度起点 | 数量与形态 |
| --- | --- | --- | --- |
| L0 主干 | 整棵树的姿态 | 先沿用现状 | 保留根盘、主轴与明显转折 |
| L1 主要侧枝 | 形成宽展、回拉、下垂等大方向 | 连接处母枝宽度的约 0.40–0.60；强枝主要可见部分约 5–10px | 每树约 3–6 条视觉主线；榉树先读出 3 条粗大扇骨 |
| L2 结构侧枝 | 让每条主枝有可辨识的分叉与转折 | 从连接处粗度推导，侧枝约为母枝的 0.45–0.60；主要部分约 2.5–4px | 每条 L1 通常 1–2 条，最强枝可 3 条；位置错开 |
| L3 末梢 | 交代收尾和植物感 | 主要部分约 1.2–2px，短末端允许更细 | 每条 L2 通常 1–2 个收尾；允许直接终止，不强制分叉 |
| L4+ | 局部细节 | 不作为常规可见骨架 | 第一轮结构方案不新增；后续只在少数强枝末端试验 |

粗度比例、像素目标是协同约束，不能通过最低宽度硬把子枝撑得比母枝粗。发生冲突时，优先减少分叉、把分叉移到母枝更粗的位置，或加强上游承重枝。文人松允许较低的像素目标，通过减少枝数和扩大留白保留清瘦感。

### 连续收分与一主一次

- 将一整条枝的弧长作为收分依据，沿途连续变细；在分叉前保留足够厚度，不提前变成针尖。多个曲线段衔接处保持宽度连续。
- 每个分叉确定一条延续原走势的长枝和一条较短的侧枝。延续枝可保留连接处约 0.70–0.82 的宽度，侧枝约 0.45–0.60；不能把每个子段都当成需急剧缩细的旁枝。
- 初始长短关系约 1 : 0.55–0.75，形成主次，不生成连续的对称 Y。子枝合计视觉重量应与母枝协调，分叉点不形成圆疙瘩。
- L1 保留 1–2 个明确动作，例如「向外—下压—抬梢」；L2 保留一个可见转折；L3 用短而干净的收尾。随机变化改变幅度和节奏，不把每段都扭成 S。
- 主侧枝基部附近保留一段不分叉的清晰路径；沿枝长约 35%–70% 的范围错位出枝，替代所有后代集中从同一处起步。

### 减量与留白

- 先分配整树和每条主枝的末梢预算，再生成分叉；达到预算就终止。第一轮每树末梢建议：真柏/黑松/斜干 18–28，榉树 24–36，文人松 8–14，悬崖 12–18，风吹 12–20。
- 上述预算指结构末梢，不要求与叶团一一对应。应允许一条末梢承载少量相邻叶团，避免一减枝就把已有冠层削空。需要同时校准叶团挂接、尺寸和密度，不能保证原叶冠逐像素不变。
- 手机中相邻重要枝线在离开共同连接点后，争取 6–10px 的可见净空；重要枝组之间争取 12–20px。真实测试不足时调整，不能只用分叉角度替代间距检查。
- 保留至少 2–3 处能直接看到背景的大空隙；不让细枝填满每个空位。避开贴着母枝并行、从主干前穿过及重叠后看似错误连接的枝线。

## 3. 七种树形各自强化什么

| 树形 | 裸枝识别特征 | 侧枝调整 |
| --- | --- | --- |
| 分层真柏 | 曲干两侧错落横展 | 低位强枝较长、先压后抬；L2 短折返，枝层间留空，避免每层同宽同形 |
| 圆顶榉树 | 从短干分出的三条粗大扇骨 | 明确三大方向，再错位分出较少的次枝；不从一个点放射出一把等粗细丝 |
| 文人松 | 长裸干、偏置小冠 | 仅 2–3 条占主导的侧枝，加一条短回枝即可；主要靠不对称和空白，不追求厚重 |
| 直干黑松 | 稳定竖轴、低宽高窄 | 下部主枝有分量，上部枝层紧凑；交替出枝，减少水平对生和规则梯形 |
| 斜干松 | 斜向主势、反向回拉 | 一条反向平衡枝与顺势长枝形成张力；两侧长度和倾角明显不同 |
| 悬崖真柏 | 抬头折返、沿垂干递减 | 分叉从弯外侧展开，向末端逐渐短细；保护折返处和盆边留白，不堆成黑结 |
| 风吹松 | 多条枝线一致扫向一侧 | L1 顺风伸展，L2 继续顺势，短回折后梢端仍回到同一方向；迎风侧留空 |

这些是待实现的视觉主线，不应通过任意删除已保存的可修剪 primary 节点来达成。

## 4. 实现建议及兼容边界

先在 Design System 建立独立的「枝干方案」对照入口，保留当前版本；不要覆盖现有「旧版形态」对照的含义。选择裸枝时，只关闭叶片，不额外偷偷加粗或隐藏枝条；完整枝叶和裸枝必须来自同一个候选结构。

建议将试验分为两个层次：

1. **收分验证版：** 在现有拓扑上辨认主枝延续和侧分叉，重算整条枝的连续粗度，验证 L1/L2 的重量与主干关系。此版用于隔离粗度问题，不作为最终方案。
2. **结构设计版（推荐目标）：** 在冻结 core/v1 之外增加侧枝生成模块，保留主干锚点和必要的一级枝身份，以少量明确控制点生成次枝，再安排末梢和叶团。使用稳定的主枝标识与路径 key，避免依赖数组长度生成跨版本不稳定的 ID。

添加独立的 branchOrder/continuation 等结构信息，不直接改现有 role 的语义。当前 role 同时影响绘制、生长、风动及修剪；榉树 bough 和 primary 的层级尤其需要明确映射。

当前剪枝命中与再生主要依赖 primary，叶团又绑定末梢节点。新结构必须验证：原有剪枝仍移除同一枝族，已剪枝不复活，再生枝继承新的密度预算和连续收分，不因减少末梢丢失叶团挂接。改变实际拓扑前，要决定旧树沿用当前生成器，还是以明确映射迁移；仅修改 VERSION 字符串不足以实现兼容，须有真正的版本分派及记录读取逻辑。

生长阶段也需要单独校准。现有粗度乘 `.04 + .96 * p**1.3`，初期会将成熟枝显著变细。幼树应优先展示较少但清楚的承重枝，细枝逐步出现；不能为满足成熟像素指标把所有新芽画成粗木棍。实际修改后应验证进度连续性与回放，而非只看成树。

## 5. 预览顺序与验收

先做真柏、榉树、文人松三种：分别暴露横展层次、密集分叉和清瘦风格的约束。通过后扩展黑松、斜干、悬崖与风吹。

Design System 审核固定：同一种子、同一成熟度、同一镜头、150% 盆器。比较当前、收分验证版、结构设计版，优先看裸枝，再看完整叶冠。用 360/390/430px 宽的手机预览，一张卡片一棵树；同时检查应用实际画布，不能用放大的桌面截图代替。

验收目标（尚未完成）：

- 不缩放页面，短暂观看约 2 秒后，可以指出主干走向、2–3 条主要侧枝及重要二次分叉；这是人工可读性验收，不是自动测试已证明的结果。
- 一次观察能区别真柏的横展、榉树的扇骨、文人松的疏枝，七种树型不退化成同一套粗 Y 枝。
- 关键 L1/L2 大部分长度满足像素目标，L3 可见但不形成毛边；末梢数量和重要枝间净空处于预算内。
- 浅色与夜色背景均可读，树和放大后的盆器均不裁切。幼苗、半成熟、成熟，以及剪后再生都要检查。
- 每种树先 review 五组固定种子，再进行更多种子的边界检查，防止只优化一个样本。
- 自动检查连接连续、收分、母子粗度关系、无环、有限坐标、确定性、枝数预算、叶团挂接、剪枝/再生/回放。视觉识别度仍须用户 review。

## 6. 研究依据

- [Bonsai Mirai — Bonsai Anatomy](https://bonsaimirai.com/blog/bonsai-anatomy)：主干线、定义方向的主枝与顶端共同组织整体走势。这里借鉴为每棵树先确定视觉主线，再安排次枝。
- [Bonsai Mirai / Peter Warren — Sustainable Design](https://bonsaimirai.com/blog/sustainable-design)：讨论二分枝序及用较少结构枝组织末梢，并说明具体目标下可有例外。这里借鉴为有预算的分叉，而非无限递归生成等分支网。
- [Bonsai Empire — Pruning](https://www.bonsaiempire.com/basics/styling/pruning)：结构修剪用于确立形态，与后续维护有所区分。这里借鉴为先审核骨架，再恢复叶冠细节。

资料提供造型原则，不提供本文的手机像素阈值、粗度比例或末梢预算；后者均为本项目的设计建议，需要用实际候选图验证。

## 7. 当前候选预览与剪枝验证

入口：`/design-system.html#branches`。真柏、榉树、文人松使用同一固定种子和应用镜头并排比较，盆器固定为 150%。手机可切换当前版、候选版或上下对照；默认先看候选版裸枝，可切换完整枝叶、五组固定样本。

根据后续真实盆景研究修正：四级以上分枝不一刀切删除，榉树保留少量末端细分枝；文人松以稀疏结构和较缓的粗度递减维持清瘦可读性，三条扇骨也不作为所有阔叶树的固定规则。参考 [榉树冬季枝形](https://www.bonsaiempire.com/tree-species/zelkova) 与 [经典树形差异](https://www.bonsaiempire.com/origin/bonsai-styles)。

`branch-design.mjs` 只由对照页显式传入 `grow` 的候选生成器选项。主干曲线和主要可剪侧枝的 ID、所属关系保留；候选重新设计侧枝粗细、错位分叉和叶团挂接。未开启该选项的应用生长、认养和存档继续使用当前生成器，不迁移已有盆栽。

样本 01 的细枝曲线段数量：真柏 138 → 28，榉树 217 → 46，文人松 75 → 21。保留所有当前可剪侧枝，分别为 6、7、5 条，确保同一个编号在两版中对应同一枝族。这是审核版本，尚未实现按手机像素自动筛选枝条或几何避碰。

顶部第二轮调整：以原始枝端高度识别冠顶 26% 的枝组，不随剪枝重新判定。真柏与文人松的主干细段使用连续粗度映射，保留基部和全部中心线；顶部主要侧枝保留 84% 的末端粗度。两种针叶树的顶部枝组减少一层，以较长的次枝直接收尾；榉树保留扇形三级分叉，但顶部不再增加第四层末梢。顶端细枝保留 56% 的末端粗度，其余末梢保留 45%，减少逐层缩成细线的现象。母子连接仍按实际连接点粗度计算，避免子枝比母枝粗。

开启「剪枝模式」显示枝条编号和大尺寸剪枝按钮。剪枝同步作用于两版，沿用 `regrowthPlan` / `appendRegrowth`；不会为美化结果重新挪动剩余枝条。可以撤销上次剪枝、恢复原树、剪去全部侧枝及推进 24 小时。只有枝量不足时才触发再生，单次剪枝不保证出现新芽。再生枝继承各版自己的枝族结构，允许再次剪除。预览不请求写入 API、不保存到真实盆栽。

自动验证覆盖：三树形五组样本的确定性、主干及剪枝身份保持、母子连接和粗细关系；剪除整枝族、叶团归属、剩余枝条不移动、撤销复原、全剪后的再生及再次修剪。候选裸枝和叶冠仍须用户审核，尤其文人松上部细枝与榉树分叉密度。现有生长比例沿用原算法，本轮交互预览聚焦成熟树及剪后再生。

第三轮调整：侧枝起始方向继承母枝在连接点的切线，再逐渐转向原有枝端，限制分叉口的突然折转。按母枝到子枝的顺序重新计算连接点，防止修改母枝曲线后出现脱接。所有枝端及叶团位置保持不变；剪枝和再生继续使用同一枝族结构。
