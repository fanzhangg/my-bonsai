# 多级分枝原型

入口：`/design-system.html#ramification`，第 10 章「枝序实验室」。只在设计系统内使用，未修改认养、存储和生产生长事件。

## 现状

`core/v1/canopy.mjs` 已经有递归细枝；`growth.mjs` 用父节点和附着位置保持生长中的连接。问题并非完全没有细枝，而是枝序没有成为明确的交互对象：`pruning-model.mjs` 的修剪点只选 `role === 'primary'`。树冠又以较大的叶层聚合，掩盖了细枝结构。

## 建议

用持久的枝条图记录 `id / parent / order / attach`，每根枝上再记录节间、顶芽、侧芽、叶量和伤口。枝序不应被固定为只能三层，也不能与渲染角色混用。初始样本展示主干 → 一级 → 二级 → 三级 → 叶簇；以后更细的萌芽仍保持真实父子关系。树冠是叶片空间分布形成的外轮廓，不是挂在枝头的单一实体。

每枝支持两种动作：疏除删除整个后代子树；回剪保留切口近端，并只删除切口远端的子树。固定种子、稳定 ID、固定相机，防止修剪后重新随机生成整树。后续接入正式模型时，需要新的版本和切口事件格式，保留旧盆栽回放兼容性。

生长应分为器官结构、资源分配和视觉表达三层。先依树种、枝龄和季节判断芽是否具备生长资格，再用光照、顶端优势和保留叶量分配生长，最后生成延长、分枝和增粗。日常天气配色不应直接决定长期枝形。

## 本轮实现与边界

- 独立的二维曲线枝条图：逐级变细、错落附着、末端小叶簇。
- 榆树、真柏两种视觉与回芽规则示意；初始三级枝序，萌芽可以继续增加枝级。
- 枝叶、透视、骨架观察；逐级选择、枝条下拉列表和可键盘操作的画布选择点。
- 整枝疏除、固定 62% 位置回剪、精确预览移除枝数与叶簇比例、撤销和重置。
- 回剪用 de Casteljau 截取原曲线，重映射保留子枝的附着参数，避免跳位或断连。
- 萌芽按钮只处理回剪后的待萌枝；榆树示意产生两个新梢，真柏裸枝不萌芽。整枝疏除不自动恢复。它是确定性的交互演示，并非植物生理预测。

本轮未实现：真实芽点与节间选择、光照遮挡竞争、季节休眠、能量与水分平衡、概率性回芽、伤口愈合、木质增粗、三维遮挡、蟠扎、与实际时间同步。62% 切口与两个新梢都是原型参数，不是园艺建议。两种树形仍共享美术骨架，后续应分别标定。

## 验收路径

1. 切到骨架，分别选择一级、二级、三级；观察每层是否从上一级枝条长出。
2. 在三级疏除一枝，再撤销；比较一级整枝疏除造成的轮廓变化。
3. 一级回剪，确认内侧子枝保留、外侧枝叶消失、其他树枝位置不动。
4. 演示萌芽，观察浅绿色新梢；选择新梢继续剪，并撤销。
5. 真柏三级回剪后演示萌芽，确认裸枝不会自动恢复树冠。
6. 窄屏使用下拉列表精确选枝，键盘可操作所有控制项。

## 资料

- [Bonsai Empire：Pruning](https://www.bonsaiempire.com/basics/styling/pruning)：区分维持性与结构性修剪，描述顶端优势、保留叶量和树种差异。
- [Bonsai Empire：Juniper](https://www.bonsaiempire.com/tree-species/juniper)：真柏修剪须保留活叶，裸木不可靠回芽。
- [Pałubicki et al., 2009：Self-organizing tree models for image synthesis](https://www.algorithmicbotany.org/papers/selforg.sig2009.small.pdf)：芽的光照/空间竞争与内部调节可用于程序化树木建模。本原型借鉴结构思路，没有复现论文算法。
