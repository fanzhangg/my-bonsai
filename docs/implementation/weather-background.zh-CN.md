# 天气与时间背景

2026-09-16。首页与领养页共享同一个环境控制器；环境与树的种子、创建时间、认领状态相互独立。同一链接在不同地点打开时，树相同，天气跟随观看者。

## 体验和视觉

- 浏览器请求位置授权。查询当前位置的近似天气与时区，按当地日出、日落安排夜色、晨光、白昼、落日渐变。无位置时只按设备当地时间显示背景，不伪造实时雨雪。
- 统一低饱和的蓝灰、苔灰、米色和淡暮粉，背景平滑过渡。树的原有叶形、叶色、树皮和盆型保留；分别调整树干、叶片和陶盆的材质颜色，按背景明度保持轮廓清晰，不再使用整树滤镜。详见 [UI 颜色设计系统](../design/ui-colors.zh-CN.md)。环境背景覆盖原外观方案中的纯色背景。
- 雨天为低密度斜雨线，雪天为缓慢飘落雪点，雾天为缓慢移动的柔和雾层，大风为轻横线，阴天为淡云层，雷雨为较深天空和较密雨线，不使用闪屏。
- 固定花盆画幅和认领前后保留 SVG 的切换逻辑不变。认领不会重置背景或粒子动画。页面不新增天气卡片；使用实时数据时，角落显示小号 Open-Meteo 来源链接。
- 系统“减少动态效果”开启时关闭粒子和雾层运动、渐变过渡。后台页面暂停动画。

## 位置、刷新和降级

本地测试可在 `.env` 设置 `REALTIME_WEATHER_ENABLED=false`，重启服务后刷新页面生效。此时完全跳过定位权限查询、位置请求、实时天气缓存和天气网络请求；服务端也禁用天气代理。保留设备时间背景及 Debug 的天气/时间预览，“恢复实时天气”也不会触发定位。设置为 `true` 可重新开启；未设置时保持开启。浏览器只接收这个布尔开关，不接收其他环境变量。

`prototype/weather.mjs` 使用浏览器 Geolocation，关闭高精度定位，在发送前将经纬度四舍五入到 0.1°（纬度方向约 11 公里，经度方向随纬度变化）。请求仅包含粗化坐标，不包含树 ID；服务器不把位置写入盆栽或数据库。定位失败/拒绝不会阻塞认领。

`GET /api/weather?lat=...&lon=...` 校验范围，再粗化坐标，代理访问固定的 Open-Meteo 域名。服务端内存缓存 10 分钟，最多 200 个位置格子。接口失败时最多使用一小时内的已有缓存，超时返回 503。

前端在可见状态下约每 10 分钟重查位置/天气，每分钟更新当地时间与渐变。会话缓存只保存天气、时区和日出日落，不保存坐标；用于首页和领养页跨导航时保持背景一致。超过一小时的缓存不再播放天气动画；天气观测时刻超过两小时也不再视为当前天气。恢复前台会检查更新时间。

生产环境定位需要 HTTPS；localhost 可开发调试。用户仍需在浏览器允许定位。当前位置实况是天气模型给出的近似状态，非现场传感器读数。

## Debug

原 `?debug=1` 面板新增：实时/晴/阴/雨/雪/雾/风/雷雨选择，当地时刻滑杆，恢复实时天气按钮。天气调试与植物年龄滑杆独立，不保存到数据库。面板明确显示定位状态、缓存状态、来源时区及当前预览时刻；未定位时显示“天气未知”。

## 实现与验证

- `weather-service.mjs`：查询、坐标校验、粗化与缓存。
- `prototype/weather-model.mjs`：WMO 天气码、当地时间和场景配色的纯函数。
- `prototype/weather.mjs` / `weather.css`：定位、会话缓存、渐变、动画、调试与可见性控制。
- 渲染器增加可选透明背景，环境使用 CSS 材质颜色 tokens，树的几何和固定镜头不变。
- 自动测试覆盖天气码、时区、过期缓存、网络故障、坐标精度、配色合法性和透明渲染不改变树形。颜色系统另有全天候对比度测试。
- 已通过本地代理使用公开柏林坐标验证真实接口；手机尺寸检查了夜间雪景和白天雨景。当前内置浏览器的实际定位测试超时，设备时间降级正常；尚未验证该设备位置授权后的实际坐标链路。

接口与 WMO 参数依据：[Open-Meteo 官方文档](https://open-meteo.com/en/docs)。数据归属和使用条款见 [Open-Meteo](https://open-meteo.com/)；当前使用无需密钥的公共接口，商用部署需按供应商当时的条款选用对应服务。

## 天气动效

天气保留天空渐变，移除全部光晕、光束和云雾叠层。雨雪与风线使用低饱和灰色与较低透明度；保留粒子数量、轨迹和速度的天气差异。页面隐藏时暂停，减少动态效果时停止动画。设计系统动效预览与应用共用同一套效果。

## 粒子运动研究与稳定化

旧实现的问题：雨速 520 px/s 乘以 0.65–1.5 的随机系数，速度差超过两倍；初始化覆盖整个屏幕，地面以下粒子同时重生；雨线角度固定，与位移方向不完全一致。

当前 `weather-particles.mjs` 将生成与轨迹计算从绘制中分离：

- 三个景深层，速度倍率 0.82 / 1 / 1.15，大小与透明度随景深关联。
- 每层均匀分配生命周期相位，再加入小幅随机扰动。横向使用低差异分布加扰动，减少空洞和扎堆。循环时不重新随机抽样，避免成批重生。
- 以稳定下落近似终端速度状态；普通雨主层约 3 秒循环，雷雨约 2.3 秒，雪约 24 秒。数值是适合二维盆栽场景的艺术化时间尺度，不是米每秒的物理标定。
- 所有粒子共享缓慢变化的横向风，雪叠加小幅局部摆动。位置由累计活动时间解析求值，避免逐帧积分误差和随机加速；页面后台暂停后恢复计时。
- 雨线长度与速度关联、方向取当前速度方向；接近花盆底部所在区域时平滑淡出。继续保留灰色、半透明和无光效的视觉约束。
- 生成数量按视口宽度与实际落地区域面积调整，有数量上限。

验证涵盖重复循环的垂直分布、速度范围、落地透明度，以及 30 / 60 / 120 Hz 采样的一致性；这不是流体模拟或雨滴碰撞求解。

参考：[NVIDIA Rain 白皮书](https://developer.download.nvidia.com/SDK/10.5/direct3d/Source/rain/doc/RainSDKWhitePaper.pdf)将雨的运动、粒子展开和渲染分离，并讨论速度与曝光对雨线的影响；[Fix Your Timestep](https://gafferongames.com/post/fix_your_timestep/)解释变步长积分的稳定性问题。本项目轨迹可解析求值，因此使用活动时间直接采样，无需引入固定步长物理求解器。

雨量调校：普通雨与雷雨基准粒子数量分别为 180 / 250，约为上一版的 1.7 倍。雨线按速度生成 18–38 px 长度；雪与风的参数保持原值。

## 晴夜星空

仅晴天夜间显示小颗粒星星，固定星位、大小与亮度错落；各自用 4–9 秒周期缓慢闪烁，不增加光晕或光束。天亮及其他天气下星空在 2 秒内淡出。移动端减少星数，后台暂停闪烁，减少动态效果时保留静态星空。应用与动效设计页共用 `stars.mjs`。
