# 手机浇水、剪枝与 Gallery 性能优化

## 实现

- 浇水时只累计实际用水量并更新水流。水流、归位和保存全部结束后更新树形；中途松手、切后台和保存失败也走相同收尾，不改变用水量与重试规则。
- 树冠簇的椭圆和枝干的精确填充碰撞规则保持不变，使用 48px 空间网格筛选候选。屏幕几何在拿起水壶、树形刷新、滚动和尺寸变化时失效，不再每帧读取整棵树。
- 水壶、剪刀的位置和归位使用 CSS translate，保留原有居中 transform。
- 剪枝保存期间准备透明位图，成功后用一张 canvas 做掉落动画；位图最长边限制 1024px，结束后释放像素缓冲。保存失败保留原枝叶；解码失败或减少动态效果时直接完成剪枝。
- Gallery 直接通过 img 加载服务端持久保存的 640×640 PNG，浏览器负责懒加载和 HTTP 缓存。列表使用 preview=1 的轻量数据；兼容旧客户端的完整列表接口仍保留。失败保留盆栽链接并提供预览重试。

树形生成算法、盆栽数据和分享图保持原有行为。Gallery 缩略图独立存储，不修改盆栽活动时间或 revision。

## 验证

- Node 24：`npm ci`、`npm test` 和 `git diff --check`。
- 自动回归覆盖空间网格与原始椭圆命中的等价性、缓存失效、动画期间不重建树、实际用水量只保存一次、保存失败和切后台收尾，以及 v2/v3 Gallery SVG 的 XML 解码。
- `node tests/watering-browser.mjs`：1280×800、844×390、320×568、390×844 下四次左右换向，水流与壶嘴误差均为 0px；启用了既有的旧 WebKit SVG 变换模拟。
- `node tests/mobile-browser.mjs`：使用独立临时 JSON 数据和 30 棵固定种子的成熟高密度盆栽，不读取 `.env` 或生产数据库。验收页可切换视口、进入详情、搜索和滚动 Gallery，并统计整树替换及位图掉落。
- 桌面浏览器 390×844 视口下，约 2.5 万 DOM 元素的树在整壶浇水期间整树替换为 0；连续剪枝确认使用位图掉落并正常收尾。Gallery 首屏约 122 个 DOM 元素、6 张位图，配色与手机布局正常，搜索与后续分页可用。

以上是桌面浏览器的手机尺寸验收，不代表真实手机帧率。上线前仍应在 iPhone Safari 和中低端 Android Chrome 上检查连续浇水、剪枝、往返滚动及发热后的帧间隔。当前没有宣称全设备稳定 60fps。

## 水流断续排查

低帧率下原实现每帧只发射一批水样本，水滴却按完整墙钟时间推进。相邻点超过 35px 时路径会断开；120ms 一帧的固定壶嘴用例出现了 11 个子路径。长卡顿还会使旧水滴越过碰撞面或寿命上限，只留下壶嘴处的新点。

水样本现在在帧间按最多 12ms 的间隔补齐，壶嘴位置在同一朝向内插值；水滴和原有用水计算共用最多前进 60ms 的动画时钟。一次较长卡顿只减慢水流推进，不会清空整条水柱。停止或换向后使用独立水流编号，不连接两次出水之间的空隙。用水上限、移出范围停止、末段滴水和碰撞位置不变。

回归覆盖 120ms 帧间隔、900ms 单次卡顿、离开/回到盆栽、末段滴水、用尽及补满。浏览器验收页新增密集 v3 树和帧间隔选项，并检查可见水流长度，避免零长度路径也被误判为“壶嘴对齐通过”。壶嘴贴着树冠时，碰撞仍可能把自由水流截短到几像素；这是与低帧率断裂不同的情况。

## Gallery 服务端缩略图

- 生产环境自动创建 bonsai_gallery_thumbnails 表（PNG 存为 bytea），每棵树保留一张最近图片；本地存入 DATA_FILE 对应的 .thumbnails 目录。缓存可跨进程重启复用，不依赖 Render 临时磁盘。
- 图片请求发现缓存缺失时在 Node 工作线程中生成；单进程最多一个生成任务执行，最多排队 64 棵树，相同树的并发请求合并。已有图片立即返回，视觉配置、剪枝、修叶、浇水数据变化或图片超过一小时后，在下一次图片请求时后台更新。不是定时任务，也不在每次浇水时阻塞生成。
- 稳定 URL 使用 max-age=60、stale-while-revalidate=3600 和 ETag；浏览器可能短暂继续显示旧图。旧图更新失败时继续保留，首次生成失败可重试。未曾生成过图片的树仍有首次生成等待。
- 自动测试覆盖并发合并、过期后台刷新、失败保留、独立本地持久化重开、PNG 尺寸、HTTP 条件请求、非法 ID 与只读树记录。Neon 的真实连接与生产部署不属于本地 JSON 测试验证范围。
