# 一盆树

新认养盆栽会随机配备八款设计盆器之一，盆形、颜色和花纹随盆栽保存。预览、认养后与再次打开链接保持一致；旧盆栽保留原盆器。见 [随机认养盆器](docs/随机认养盆器.md)。

手机优先的 Prototype：首页每次刷新出现随机幼苗，一键认领眼前这棵树；通过固定链接回来观察生长，打开时自动快速回放。认养后可以拖动右下角剪刀，松手剪除旁支，主干始终保留。

沿用七款树形与六套视觉方案；当前不提供命名或参与者。基础实现见 [应用 MVP 实现](docs/应用MVP实现.md)，新增剪枝行为见 [剪枝交互实现](docs/剪枝交互实现.md)。

首页左上角的网格图标打开 `/gallery`，入口仅在首页显示。小院展示最多 200 盆已认领且有访问或操作记录的盆栽图片，使用各树配色对应的背景，无标题、文字或边框，仅在左上角保留返回首页的箭头图标；按最近活跃时间（互动、访问中较晚的一次）倒序。图片按当前生长和剪枝状态绘制，点击即可探望。

每批只读取 24 盆，滚动接近底部时通过游标加载下一批，累计到 200 盆即停止。浏览器只绘制视口附近的 SVG，远离视口的图形释放，返回时重新绘制；逐盆让出主线程，避免一整批绘制阻塞操作。翻页期间排名发生变化的树会在刷新后重新排序。`activity.mjs` 中的 `GALLERY_LIMIT` 和 `GALLERY_PAGE_SIZE` 控制总上限与每批数量；本地测试不代表生产数据库和移动设备的延迟。

成功剪枝、保存作弊修改记录服务器实际互动时间；打开树页面（包括认领后继续观看）、重新切回可见页面记录访问时间。定时同步、加载 Gallery 和缩略图不计访问，也不修改树的版本。现有记录以历史剪枝时间兼容，过去未记录的访问无法补回。当前没有账号或所有者身份，互动指树页面上的成功操作。PostgreSQL 和本地 JSON 均支持保存活动记录和查询 Gallery。

## 分享盆栽

领养后右上角的分享图标会打开当前盆栽的缩略图和浇水邀请。支持 Web Share 的设备可打开系统分享；支持文件分享时还会附上 PNG。其他浏览器可复制邀请文案与固定链接，或保存图片。取消系统分享不会自动复制或发送内容。

`/t/:id` 的初始 HTML 含 Open Graph / Twitter 分享标题、描述和绝对图片地址；`/t/:id/share.png` 根据该树已保存的生长、剪枝、浇水和盆器生成 1200 × 630 PNG，不依赖爬虫执行 JavaScript。预览请求不记录访问、不修改盆栽。图片版本随修订和分钟更新，服务端最多缓存 32 张，HTTP 缓存一分钟；社交平台可能另有预览缓存及裁剪方式。草稿修改需要保存后才会进入分享图片。

绝对链接优先采用 `PUBLIC_BASE_URL`，其次使用 Render 自动提供的 `RENDER_EXTERNAL_URL`，未设置时使用请求主机及 HTTPS 代理协议。使用自定义域名可设置 `PUBLIC_BASE_URL=https://你的域名`。本地验证不代表已完成微信等第三方平台或生产域名的实测。

## 本地运行

需要 Node.js 22.9+，推荐 24。

```sh
npm ci
npm start
```

打开 [一盆树](http://127.0.0.1:4173/)。默认使用 `data/trees.json` 持久保存本地盆栽。

```sh
npm test
```

## 开发与持续集成

日常开发使用 `dev`；`main` 保持为 GitHub 默认分支和部署分支。流程为：

```text
提交并 push 到 dev → GitHub Actions: npm ci + npm test → 成功后自动快进合入 main
```

本地首次使用：

```sh
git fetch origin
git switch dev
git branch --set-upstream-to=origin/dev dev
```

如果本地尚无 `dev`，使用 `git switch --track origin/dev`。之后在 `dev` 上正常 `git commit` 和 `git push` 即可；`commit` 只写入本地，`push` 才会触发 CI。不要直接向 `main` 推送开发改动。

工作流位于 `.github/workflows/ci.yml`，使用 Node.js 24。向 `dev` / `main` 推送，以及以这两个分支为目标的 PR，都会运行测试；只有 `dev` 的 push 或手动运行会在测试成功后自动更新 `main`。测试失败、取消或超时时不会更新 `main`。新提交会取消同一分支的旧运行，合入前还会检查 dev 是否已有更新。

`main` 的 GitHub 分支保护要求来自 GitHub Actions 的 `Tests (Node 24)` 检查通过，对管理员同样生效，并禁止强制推送和删除。自动合入使用通过测试的原始提交 SHA，仅允许快进；若 `main` 出现独立提交导致分叉，在 `dev` 合入 `origin/main` 后重新 push，CI 会测试合并后的结果。

CI 使用仓库自带的 `GITHUB_TOKEN`，无需额外 PAT 或生产数据库密钥。测试任务只有读取权限，合入任务才有写入权限，且不运行应用代码。GitHub 不会因为这个 token 更新 `main` 再触发一次 push 工作流；该提交已在 dev 测试完成。未来新增 GitHub Actions 部署时，应接在此流程后，不能依赖这次自动合入触发另一个 push 工作流。

Render 的部署分支应设置为 `main`。当前测试覆盖应用逻辑和本地 JSON 存储，不包含真实 Neon 数据库、生产部署或完整浏览器视觉验收；自动合入代表现有测试通过，不保证所有线上场景均已验证。

## Render + Neon

仓库包含 `render.yaml`。在 Render 设置 Neon 的 `DATABASE_URL` 后部署。生产模式强制使用 PostgreSQL；未配置数据库不会启动。本地可复制 `.env.example` 为 `.env` 后填写连接串，启动命令会自动读取。

当前尚未连接真实 Neon 或部署 Render；本地功能可直接体验。

## 作弊模式与算法研究

- [设计系统 · 树形谱系](http://127.0.0.1:4173/design-system.html#trees)：新版粗干收分与差异化冠形，可切换旧版、裸枝、剪影及五组样本。见 [盆景形态研究与改进](docs/盆景形态研究与改进.md)。

在盆栽链接末尾加 `?cheat=1`（兼容 `?debug=1`），进入作弊模式：调整时间、树形、外观、种子或剪枝后，点击“保存到这棵树”即可持久保存，刷新或退出模式后仍然保留，并从保存后的年龄继续生长。首页调整后的样本会在认领时一起保存。更换树形或种子会清空旧剪枝，单独换外观会保留剪枝；“重新载入已保存状态”可丢弃未保存的修改。天气和当地时刻仅供预览。

首页和领养页共用当地时间渐变及实时天气动画；需要浏览器定位授权，位置不可用时回退到设备时间。Debug 可单独预览天气和时刻，详见 [天气与时间背景](docs/天气与时间背景.md)。
